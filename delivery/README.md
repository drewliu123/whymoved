# 历史交付索引

本目录保存既有交付快照、清单与报告副本。包名中的版本代表当时交付，不表示当前源码版本、最新安装包或已重新验证的运行结果。安装和当前用法以[项目说明](../README.md)为准。

## 代表入口

| 入口 | 性质 |
|---|---|
| [META 历史文字报告](meta-nov-20261102/META-2026-11-research.md)、[HTML 报告](meta-nov-20261102/META-2026-11-research.html) | 当时研究内容的交付副本；应按原研究截点阅读，不当作当前行情或新核验结论。 |
| [META 转换记录](meta-nov-20261102/provenance.json) | 记录冻结报告哈希与版式转换范围；其中历史本机绝对路径属于原始记录，不重写成新运行证明。 |
| [manifest.json](manifest.json)、[0.3.1 清单](touyan-0.3.1-manifest.json) | 对应旧交付批次的清单，使用时核对实际包及版本。 |
| [0.3.0 源码包](touyan-0.3.0-source.zip)、[0.3.0 验证包](touyan-0.3.0-validation.zip)、[0.3.1 源码包](touyan-0.3.1-source.zip) | 历史 ZIP，完整保留原名称、内容与路径，不覆盖为新版。 |

## 后续打包建议

需要重新生成 ZIP 时，建议从明确的 tag 或提交生成新的版本包，并作为 GitHub Release 附件发布，附源码提交、生成方式、内容清单、校验和及验证范围。依赖运行时、子模块和必要的离线材料是否包含，应在该次 Release 中写明。包中不应夹带本机配置、凭据或可重新获取的运行缓存。

该建议不要求删除现有 ZIP，也不改变既有交付记录。新版本使用新文件名和新清单，旧包保留；报告修订另存版本并关联原件，不重写历史。研究过程见[研究档案](../journal/README.md)，保留规则见[档案策略](../docs/archive-policy.md)。
