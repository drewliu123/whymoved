# 本地接入约束：主代理复核基准

本轮只做研究评级，不修改生产实现。

## 已核对的本地事实

- scripts/check_claims.py 检查结论结构、来源标签、数量与可解析日期，不计算概率、不判断语义蕴含。预测后端不应与证据校验器混为同一模块。
- scripts/journal.py 假设结构已经容纳 my_prob 与 market_prob；brier 函数仅做平方误差。概率合法范围、概率所对应的明确事件、校准版本与预测时间轨迹尚无独立强制契约。
- 当前 outcome 用 hit/miss/void 表示假设成败；外部预测器若预测 YES 概率，需要明确其与假设真值的对应，不能把交易动作对错当事件真值。
- 归档包含报告、证据、假设与计划，可在旁路新增预测原始值、聚合值、校准值及证据快照，不必首先引入整个多 Agent 框架。
- 现有脚本标准库为主；引入 pandas/scipy/pytorch/框架服务属于实际维护成本，评级时应显式记录。

## 复核时关注

代码A级仅表示在读到的静态实现中，有可提取并适配的独立模块，不表示效果经过验证。若许可状态阻止直接复制，应降到C或给出“仅参考重写”限定；不能把完整项目笼统打A级后隐藏风险。

方法A级仅表示对目标缺口直接相关且可解释，不是实证效果排名。论文A/代码N可以同时成立；README可读但算法未读时，代码U通常比猜测B更诚实。

最终交付必须分别显示原作者/第三方、当前工程版本/论文版本、模块评级/整项目迁移，以及未运行验证状态。
