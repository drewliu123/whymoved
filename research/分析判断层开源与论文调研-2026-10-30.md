# 投研助手分析判断层：开源与论文调研

调研日期：2026-10-30。目的：为现有证据检索—账本—反方—备忘录—假设复盘流程补充分析、概率估计与决策支持。本文是设计研究，不表示新功能已实现，也不表示已复现任何论文收益或预测成绩。

**后续更新：** 初筛后的多代理关键源码审查见[复用评级总表](复用评级总表-2026-10-30.md)。该轮已确认CAIS官方demo源码、补读LEAP等论文方法、发现若干许可与实现差异；本文件的原核验范围与初步优先建议不应当成最终选型结论。

## 核心判断

不存在本轮已证实能直接接入、普遍适用于事件、股票、主题和人物研究的高质量决策模型。更可行的组合是：可裁决的问题定义 + 类型适配的数值模型 + 证据更新 + 独立预测聚合 + 反证与敏感性分析 + 时间外校准和评价 + 独立的行动决策层。

最优先研究 forecasting-tools 的接口、Halawi 的检索与概率聚合流程、BLF 的结构化信念状态、ForecastBench 的前瞻评价。LEAP 的证据贡献思路值得借鉴，但当前公开仓库不含完整概率后端。股票估值借鉴 FinRobot；统一数值实验借鉴 Qlib；交易研究评价借鉴 FINSABER。

不能把 Agent 的 confidence、名人角色投票、情绪标签、收益排序分数、RL 动作概率直接当成事件发生概率。模型报出百分数并不代表已经校准。

## 一、事件概率预测：优先借鉴的工作

### 1. Metaculus forecasting-tools：工程骨架

- 官方：https://github.com/Metaculus/forecasting-tools
- 提供二元、多选、数值、日期问题契约；研究、多次独立预测、聚合与报告保存的可替换接口；模型包装、结构化输出、重试和成本跟踪。
- 对我们最有用：把研究输入、原始预测、聚合预测和最终报告定义成明确对象，而非只输出一段文字。
- 边界：框架不是已验证的单一预测算法；有校准组件不表示默认所有输出均经过有效校准。具体默认聚合公式应以采用的代码版本为准。

### 2. Halawi 等：Approaching Human-Level Forecasting with Language Models

- 论文（2024）：https://arxiv.org/abs/2402.18563
- 代码：https://github.com/dannyallover/llm_forecasting
- 作者说明：https://www.alignmentforum.org/posts/K2F9g2aQubd7kwEr3/approaching-human-level-forecasting-with-language-models-2
- 流程：生成查询 → 按时点检索新闻 → 相关性筛选 → 针对问题压缩证据 → 多次推理与概率预测 → 截尾均值聚合。另有筛选推理样本与微调。
- 作者报告测试集整体 Brier 0.179，群体预测 0.149（低者更好）；只有特定筛选子集超过群体。不能写成整体超越人类。
- 借鉴：先建立简单、透明、可比较的概率基线。保留每次独立预测与证据摘要；聚合规则预先固定。
- 边界：旧模型和新闻接口依赖；历史检索与模型知识截止约束仍不能完全证明没有泄漏。

### 3. BLF：Agentic Forecasting using Sequential Bayesian Updating of Linguistic Beliefs

- 论文（2026）：https://arxiv.org/abs/2604.18576
- 已读取 v1：https://arxiv.org/html/2604.18576v1
- 核心（源码/正文复核后更正）：维护结构化信念状态，记录当前概率与自然语言证据总结；每轮工具调用后更新；独立多次试验；论文默认在概率空间取算术均值，另实验 logit 收缩；分来源的层级 Platt 校准。论文正文明确收缩在 ForecastBench 上伤害所比较指标，不能把第三方默认收缩实现等同原论文默认算法。
- 作者在 400 个 ForecastBench 回放问题上报告较强成绩，并给出消融；原文明确说回放结果不必然迁移到实时预测，主要基模结果也不必迁移到其他模型。
- 校准使用 leave-one-out；这与严格“只用过去已结算样本训练，再预测未来”的时间外部署评价不同。我们的校准必须另做滚动时间切分。
- 借鉴：用可检查的信念状态替代不断膨胀的检索上下文；记录每次更新理由、变化、反证和未决变量。
- 不宜直接照搬：模型自己说“贝叶斯更新”不等于似然有统计依据。不同模型混合也未必提高质量，原文有集成无收益或下降的结果。
- 开源边界：本轮未核实作者官方完整实现；检索到的 swarm-ai-research/blf-forecaster 自称第三方重实现，不应当成论文作者代码。

### 4. LEAP：Likelihood Elicitation and Aggregation for LLM-based Probabilistic Forecasting

- 官方介绍：https://layingfish.github.io/LEAP/
- 论文（2026）：https://arxiv.org/abs/2609.01337
- 仓库：https://github.com/layingfish/LEAP
- 方法：固定证据集；模型逐条解释证据并估计局部似然参数；明确先验；确定性概率更新；通过删除单条证据后重算，显示其贡献。
- 官方介绍报告同证据条件下多数预测与校准指标改善；这是作者实验结论，未在本项目复现。
- **重要代码核验**：公开 tree 包含 SKILL.md、finalizer-contract、normalize_agent_trace.py 与论文/网站等；SKILL 明确定位为适配器，要求外部 AGENTFUTURE_FINALIZER_BIN；契约明确“probability model itself is supplied by a separate executable”。公开 normalizer 负责证据规范化与 hash，不是完整似然聚合器。因此当前不能把它列为现成可运行的完整概率引擎。
- 借鉴：证据冻结、相同输入的成对比较、先验透明、单证据贡献审计。
- 风险：多个证据可能是同一事件的转载或相关信号，不能简单把似然比相乘；模型估出来的局部似然本身也需验证。敏感性范围不应冒充统计置信区间。

### 5. Consistency Checks for Language Model Forecasters

- 论文（ICLR 2025）：https://arxiv.org/abs/2412.18544
- 代码：https://github.com/dpaleka/consistency-forecasting
- 用否定、合取、析取、条件、同义改写等相关问题检查概率是否一致，并尝试通过套利优化修正。
- 借鉴：发布前检查 P(A)+P(not A)=1、多选总和、条件与包含关系。
- 边界：一致性不等于准确性或校准；论文不支持“一致性修正必然改善真实结果”。

### 6. OpenForecaster：模型训练路线，后置考虑

- 论文：https://arxiv.org/abs/2512.25070
- 代码：https://github.com/OpenForecaster/scaling-forecasting-training
- 项目：https://openforecaster.github.io/scaling-data/
- 从新闻生成问题，使用离线时间语料检索与强化学习后训练；开放模型、数据和训练代码。
- 借鉴：将最终结果作为监督，积累专门预测数据；固定检索语料。
- 边界：自由文本答案的 confidence 与完整互斥概率分布不同；我们还没有足够可靠的标注和评价数据，先不以微调为首要工作。

### 7. AutoCast：早期证据到预测的可训练基线

- 代码：https://github.com/andyzoujm/autocast
- 论文：https://proceedings.neurips.cc/paper_files/paper/2022/file/aec870a6772336c15dac992c16f2e7c9-Paper-Datasets_and_Benchmarks.pdf
- 检索、重排、新闻编码与时间聚合，学习事件预测。适合借鉴随证据到来更新预测的轨迹。
- 旧模型系统，不是现成现代 Agent；官方注明 Metaculus 数据研究用途限制，不能默认商用与再分发。

## 二、金融分析与决策：借流程，不能借一个未经校准的 confidence

### 8. FinRobot

- 代码：https://github.com/AI4Finance-Foundation/FinRobot
- 平台论文：https://arxiv.org/abs/2405.14767
- 估值论文：https://arxiv.org/abs/2411.08804
- 财务数据 → 数据与概念分析 → 投资论点 → DCF/相对估值 → 风险解释。当前工程版本与原 AutoGen 论文版存在演进，不混用证据。
- 借鉴：模型提出假设，代码计算增长、利润率、折现、终值和情景估值；报告说明估值对关键假设的敏感性。
- 估值区间不等于价格达到该区间的概率；长期可交易超额收益尚未由本轮材料证明。

### 9. TradingAgents

- 代码：https://github.com/TauricResearch/TradingAgents
- 论文：https://arxiv.org/abs/2412.20138
- 更新：https://github.com/TauricResearch/TradingAgents/blob/main/CHANGELOG.md
- 分工分析 → 多空辩论 → 研究经理 → 交易观点 → 风险辩论 → 组合决策。
- 借鉴：反驳必须针对关键变量，结论与风险约束分开；不要增加角色数量后直接以投票代替概率。
- 官方 v0.4.0 更新明确承认修复历史宏观请求使用今天修订数据的前视问题；其他更新涉及社交内容、结果记忆、财报可用时点与成交评分。工程修复不等于原论文成绩被重新验证。

### 10. Qlib

- 代码：https://github.com/microsoft/qlib
- 论文：https://arxiv.org/abs/2009.11189
- 数据/因子 → 模型训练 → 预测分数 → 组合 → 成本后回测。适合数值基线、实验记录与时序验证。
- 收益预测 score、横截面 rank 与 IC 都不是上涨概率。未来收益标签可用于训练，不能混进特征；拟合预处理也只能使用训练期数据。

### 11. AI Hedge Fund

- 代码：https://github.com/virattt/ai-hedge-fund
- 投资风格/专长分析 → signal/confidence → 风险限额 → 组合动作与账本。
- 借鉴：确定性风险限额与独立决策账本。名人角色包装与意见一致程度不提供概率校准证明。
- 属研究/教育性质；本轮未核实长期前瞻超额证据。

### 12–15. 补充项目

- FinGPT：https://github.com/AI4Finance-Foundation/FinGPT ；论文 https://arxiv.org/abs/2306.06031 。适合文本抽取和情绪特征；Forecaster 的方向类别与解释不自动构成校准概率。
- FinRL：https://github.com/AI4Finance-Foundation/FinRL ；论文 https://arxiv.org/abs/2011.09607 。优化环境中的累计奖励与仓位，动作概率不是结果概率；目前不是我们的首选分析层。
- FinMem：https://github.com/pipiku915/FinMem-LLM-StockTrading ；论文 https://arxiv.org/abs/2311.13743 。借鉴分层记忆与信息时效；历史回放必须禁止未来已结算经验被早期任务读取。
- FinAgent：https://github.com/DVampire/FinAgent ；论文 https://arxiv.org/abs/2402.18485 。借鉴工具化分析与反思记录；本轮没有全文复核成本、污染和显著性，不能据摘要认定投资优势。

### 16. predict-raven：预测与行动分层的工程样例

- 代码：https://github.com/Alchemist-X/predict-raven
- 相关论文：https://arxiv.org/abs/2607.03015
- README 描述市场盲预测、独立证据更新、模拟交易、订单簿滑点、费用、净优势退出与风险约束；体育路线使用 Elo/赛程模拟等领域模型，而不是让 LLM 凭空生成所有概率。
- 借鉴：先形成独立预测，再读取可成交价格并比较；“预测准”与“赚到钱”分别评价。
- README 也记录过搜索返回验证码页却被当成无证据的故障。借鉴明确失败状态，不能把来源失败解释为没有相关信息。
- 公开运行/收益叙述不等于独立审计。本轮只核验 README，不背书效果，也不借用其具体仓位参数。

## 三、评价与防泄漏：与分析模型同步建设

### 17. ForecastBench

- 代码：https://github.com/forecastingresearch/forecastbench
- 论文：https://arxiv.org/abs/2409.19839
- 文档：https://forecastbench.org/docs/
- 未来题提交、事后裁决、动态评价、难度调整与可比较榜单。它是评估设施，不是概率模型。
- 我们先采用同一批问题上的配对 Brier/log loss、可靠性图、样本量与不确定性，不必复制完整榜单体系。当前 Brier Index 与老论文 raw Brier 不是同一数值，不能横比。
- 市场概率输入必须显式记录；有市场输入的模型必须与直接复制市场概率的基线比较。

### 18. FINSABER

- 代码：https://github.com/waylonli/FINSABER
- 论文：https://arxiv.org/abs/2505.07078
- 扩大周期与股票池后，原先 LLM 优势会显著衰减；这提醒我们不能以少数股票短期漂亮收益选模型。
- 当前 FINSABER-2 明确执行时点、复权 OHLC、滑点、流动性、结构产物与 LLM 成本；复现原论文使用 reproduce 分支，不能直接把当前 main 当原实验。

### 19. Temporal Leakage in Search-Engine Date-Filtered Web Retrieval

- 论文（ACL 2026）：https://aclanthology.org/2026.acl-short.65/
- 该实验中，Google/ DuckDuckGo 日期过滤后至少有一篇严重穿越文档的问题分别占 71%/81%；直接透露答案 41%/55%。在所测模型/题集上，泄漏材料 Brier 0.10，干净材料 0.24。数字限于该研究，不代表所有检索。
- 日期字段过滤不够：旧网页更新、相关内容模块与错误元数据仍泄漏。应使用冻结时间语料；最可信的本地验证是先记录未来预测，再等待裁决。

### 20. 评价理论与补充阅读

- Gneiting & Raftery, Strictly Proper Scoring Rules, Prediction, and Estimation：https://doi.org/10.1198/016214506000001437 。使用 proper scoring rules，区分校准与有信息量的概率。
- On Calibration of Modern Neural Networks：https://arxiv.org/abs/1706.04599 。可借校准思路，分类器温度缩放不能不经检验直接套给跨领域 LLM 预测。
- Pitfalls in Evaluating Language Model Forecasters：https://arxiv.org/abs/2506.00723 。补充预测评价陷阱。
- CruxBench：https://arxiv.org/abs/2609.35879 。按信息价值判断哪些子问题值得追问；本轮仅检索摘要，暂列候选，不作为已审计实现。

## 四、建议的新分析判断流程

以下为本项目设计建议，尚未实现或证实优于现流程。

### A. 把研究对象变成可检验目标

明确事件/数值、期限、互斥选项、裁决规则、as_of、预测要支持的选择。对主题/人物的开放问题，先交付机制与情景，不强求每一段内容都有概率。

产物：question_contract。模糊结算或无法定义对象时停止报精确概率，返回研究性结论及所需条件。

### B. 路由到匹配的方法

- 明确事件：历史参考类与基准概率 + 条件情景/证据更新。
- 公司估值：财务驱动、DCF/相对估值、情景与敏感性；“低估”不直接转成上涨概率。
- 连续数值/价格：可用数据上的统计/量化基线与预测分布，按时间切分评估。
- 开放主题/人物：机制、关键变量和可验证里程碑；证据不足时不编造数值。

先定义接口和简单基线，再决定是否引入训练模型、复杂贝叶斯网络或模拟。

### C. 建立显式基准并冻结证据

记录基准的来源、样本、统计口径与局限。为测独立研究价值，主预测分支先屏蔽市场价格，独立形成 p_independent；另设允许市场输入的分支 p_market_assisted，分别评价。市场只是有力基线，不能既锚定市场再把相近概率当独立发现。

证据包含 published_at、retrieved_at、可用时点、原文版本和 hash；按同源事件聚类，避免同一信息多次加权。当前检索框架负责供应这些信息。

### D. 形成结构化信念状态

记录：当前假设、关键变量、支持/反对证据、独立信息簇、基准概率、更新理由、当前未解决问题、最可能推翻判断的条件。

LLM 负责提出机制与解释证据；可计算的数值由代码计算。局部似然只能在有定义、相关性处理与敏感性检验后使用；没有基础时采用明确标注的判断性概率基线。

### E. 两种概率路径同场比较

路径一：简单透明基线——相同冻结证据，多次独立预测，固定均值/截尾均值/中位数中的一种规则；方法选择只在开发集完成。

路径二：结构化路径——明确先验、独立证据簇、证据贡献/情景条件，由确定性计算器汇总。可借 LEAP 方法，但后端需自建或核验另一个完整开源实现，不能误以为现有仓库已提供。

两条路径使用同样证据、基模与相近预算，才能区分结构收益和额外算力收益。

### F. 反证、一致性与敏感性

反方只攻击关键假设和证据贡献；有新材料则新版本冻结后重算。检查互斥概率总和、否定与包含关系；改变基准、关键参数与证据簇，说明结论是否翻转。模型间分歧、敏感性范围和统计置信区间分开命名。

产物：p_raw、每次独立预测、p_aggregate、敏感性范围、分歧来源与 abstain 原因。

### G. 校准与前瞻评价

校准模型只用预测当时已经裁决的历史样本拟合；原始、聚合和校准概率都保存。没有足够代表性的样本时，标为未校准，不凭口头承诺称已校准。

配对比较：现有整体判断、基准发生率、直接复制市场、简单聚合、结构化更新。二元用 Brier/log loss，多选用适当多类评分，数值用 CRPS/WIS 等；报告可靠性、分辨能力、覆盖率/拒答率、成本和时延。相关同事件按组切分与估计不确定性，避免一个事件多时点被当独立样本。

优先前瞻记录未来题。历史回放须冻结语料和价格/财报版本，并披露基模知识污染风险。不能随看测试成绩随改提示后仍把该测试集当未见样本。

### H. 独立决策层

在概率/估值形成后，读取可成交价格、收益结构、成本、流动性、期限及用户约束，比较行动、等待和补证据的价值。证据或优势不足允许“不行动”。

对结算为 0/1 的 YES 合约，持有至结算、每份成本 q、额外期望成本 c 的简化期望净收益是 p-q-c；必须明确该公式不覆盖提前退出、复杂费用、资金占用及非二元资产。不要用未经校准概率直接驱动 Kelly 仓位。

冻结决策依据与拒绝原因；预测质量与行动收益分别复盘。当前项目定位限制买卖建议，正式启用具体行动输出前需修改产品契约；本次调研不更改现有边界。

## 五、落地顺序与验收

先建题目契约、冻结证据、简单概率基线与评价接口；接着加入结构化信念更新和敏感性；用同题同证据比较；最后接决策规则。不要先微调模型、复制整个多 Agent 基金，或增加大量检索平台。

验收不以报告更长或角色更多为依据：能重算、能解释差异、能拒绝无依据概率、能在时间外同题比较中产生稳定增量，并能看到成本代价。有限样本只能给初步信号，不能提前宣布胜过市场。
