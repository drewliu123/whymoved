**输入 → 处理 → 输出。** `DCFInputs` 接收收入基数、增长路径、利润率、折旧、资本支出、ΔNWC、税率、资本成本参数、股数与净债务。收入逐年增长；FCF=`(EBITDA−D&A)(1−税率)+D&A−CapEx−ΔNWC`；CAPM 计算股权成本，按资本结构计算 WACC；折现显式期现金流与 Gordon 终值；EV 减净债务除股数得到每股估值及中间项。终值维护性资本支出采用 `min(D&A比例, CapEx比例)` 锚点，ΔNWC 可采用单独终值比例。该经济假设必须进账本，不能称为无假设“真实价值”。

`calculate_dcf` 拒绝终值增长不低于 WACC、Gordon spread 过小、终值 FCF 非正或股权价值非正；敏感性表对应无效单元返回 None。输入模型约束股数正、部分比例范围、非有限收入/净债务/增长。函数的 override 与直接构造输入仍需额外边界审查，不能认为模型验证覆盖所有调用方式。

MC 用 NumPy 高斯扰动与对偶变量，部分域采用对称截断；强制终值增长不超过 WACC 减最小 spread；丢弃终值 FCF 非正/价格不足 0.005 的路径，再用 3×IQR 栅栏移除尾部，至少保留 100 条才出统计。输出估值样本、分位数、直方图、当前价格在分布中的位置与实际有效条数。它是**给定人为分布、夹紧和筛选规则后的条件估值分布**，没有在已读部分见到把它校准为未来市场价格分布的拟合或覆盖率检验。

**具体可复用项。** `calculate_wacc` 是可直接适配为标准库算术的完整纯函数；`calculate_dcf` 的分期现金流、EV→股权桥与异常降级契约；`calculate_sensitivity` 的无效单元语义；将假设、数值结果与模型解释分离的模块边界。`compute_signal`/`compute_hit_rate` 可以借状态契约，但要改成自己明确的裁决定义。A 级来自这些已读完整算子，而不是桌面 UI、角色数或 README 的生产称谓。

**不可直接复用项与原因。** MC 默认噪声、参数独立性与删尾没有市场概率校准；非对称 Blume 调整是仓库作者的先验选择（只收缩高 beta），不能借经典名称视为普适事实。`audit_narrative_numeric_grounding` 只剥除年份/序数后查是否有数字，不核该数字是否真在来源/白名单，也不阻止决策；它是轻量提示，不能充当本地证据校验器。`compute_signal` 实际以预期变动距离归一化、走完超过一半路程就记 hit，而文件头和 docstring 仍有“目标价 ±10%”旧说明；命中可先于七天宽限返回。`compute_hit_rate` 不校验 `closed_returns` 和 signals 一一对应。该命中率不可宣传成到期目标价命中率或 Brier。

V0 的 `get_risk_assessment` 是拿 10-K 1A 后生成风险摘要提示，没有硬仓位风控；`BackTraderUtils.back_test` 动态导入自定义类、取 yfinance 复权数据并运行 Backtrader，已读函数未设置显式手续费/滑点，不适合作为本地插件可信代码执行接口。

**依赖与许可。** 根/桌面 Apache-2.0（保留许可、修改说明、适用 NOTICE；商标使用另有政策）。桌面声明 Python≥3.11、Pydantic-AI/settings、FastAPI、yfinance、edgartools、ddgs 等；MC 明确导入 NumPy，当前所读桌面依赖列表没有直接列出 NumPy，应核间接依赖和锁定方式，不能承诺独立复制即运行。V0 数值回测依赖 Backtrader/yfinance/matplotlib/IPython。第三方依赖许可证未逐包审计。LLM 为外接服务，模型许可/服务条款未核实。FMP、Finnhub、Yahoo、SEC、Damodaran 派生数据的授权与再分发边界分别未核实；NOTICE 将 FMP 标为 commercial，不等于取得数据商用权。

**名称与链接 / 类别 / 评级。** [官方仓库](https://github.com/microsoft/qlib)；量化数据、特征、模型、策略、交易模拟与风险评价。当前代码 B、方法 B、E2：已读数值与策略实现，但相对标准库研究插件过重，主要适合评价/数值侧的独立适配层。

**输入 → 处理 → 输出。** Alpha158/360 的 handler 配置特征、训练/推理处理器与拟合起止时点，默认标签 `Ref($close,-2)/Ref($close,-1)-1` 是未来收盘收益，学习处理器可丢空标签并作横截面标准化。模型的分数进入 `TopkDropoutStrategy`，策略在当前交易步读取 shift=1 的前一步信号；排序选 topk，每次替换 n_drop，可按可交易性筛选、检查持仓天数，并对卖出后的现金生成买单；DataFrame 信号只使用第一列。输出是订单对象及模拟结果，不是事件概率。

Exchange 成交内核先按容量削减订单，然后成本率=`open/close_cost + impact_cost×(交易额/期间总成交额)^2`；再按持仓、现金、最小费用和交易单位限制数量。最终费用=`max(交易额×成本率,min_cost)`，未成交为零。所读默认 impact_cost 为 0，不能因为“支持冲击”就说所有现成实验已启用冲击；内核还注明数量在后续削减时先算的冲击可能高估。卖出分支按现有持仓上限削减，且有 `TODO shortable`，不能当成通用空头执行器。

`risk_analysis` 输入收益 Series：默认 sum 模式以均值×年化系数、累计和回撤、均值/样本标准差×sqrt(N) 输出；day 默认缩放是 238 而非参数说明里常见的 252。product 模式使用累计乘积和几何年化，std 用对数收益，名为 information_ratio 的分子则是几何每期均值；它的定义需要随结果披露，不能直接与别处 Sharpe 比较。

**可复用项。** 学习/推理处理器分离和 fit 时间窗的契约；收益分数与执行步错开的接口；策略输出 Order、交易所独立处理费用/容量/现金的分层；`risk_analysis` 算法可拆作标准库版本但必须显式选择年化/复利约定。协方差收缩可参考 Ledoit-Wolf 分支结构，但仍需独立数值对照与退化样本测试，不能由读源码自动提升为正确性验证。

**不可直接复用项及具体问题。** OAS 分支 [`_get_shrink_param_oas` L167–186](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/model/riskmodel/shrink.py#L167) 自己的文档公式是 `A=(1−2/p)tr(S²)+tr(S)²`、`B=(n+1−2/p)(tr(S²)−tr(S)²/p)`，代码却为 `A=(1−2/p)*(trS2+tr2S)`、`B=(n+1−2/p)*(trS2+tr2S/p)`，与其声称公式在乘法位置/分母加减号上冲突；返回值没有像 LW 分支一样 clamp 到 [0,1]。这是静态确认的实现/注释不一致，本轮未运行、未证明具体收益影响，也不扩大到所有风险模型。该分支**不可直接复用**，需对照原论文与参考实现修正并验证。

常数相关性目标涉及方差开方和除法，单资产/零方差/缺失情况要另验；已读 risk_analysis 不保护空样本、零波动、r≤−1 的对数输入。标签中的负 Ref 是合法未来监督目标，必须保证不进入推理特征，不能仅因出现负 Ref 断言泄漏，也不能仅因有 fit_start/end 就认定全链路无泄漏。topk/risk_degree 不是概率或风险预算校准。整体仓库不是低依赖的现成概率后端。

**论文版。** 读到 [原平台论文 v1](https://arxiv.org/html/2009.11189v1)，2020-09-22；读取平台模块化数据处理、时序再训练/超参搜索与 §5 性能评价。其明确的性能实验主要是 HDF5/MySQL/MongoDB/InfluxDB/Qlib 的数据查询与处理速度，采用 2007–2020 OHLCV、每日变化的约 800 股股票池和 14 因子；表达式/数据缓存的加速不能解释成交易超额收益证明。论文强调随时间变化的 instrument pool，值得用于防存活者偏差；但本轮未锁定 2020 对应代码，也不将 2026 新增策略/风险模型算入论文实现。论文版代码 U、方法 B、E2。

**输入 → 处理 → 输出。** LLM Agent 输入按时点取得的基本面 snapshot；数据不足或 LLM/解析失败产生明确 `metadata.abstained=True`；其他数据错误向上抛出。合法 JSON 为 bullish/neutral/bearish、confidence 0–100 与 reasoning，转为 `Signal.value = sign × confidence/100`，并带 prompt_key、snapshot_hash、模型、是否缓存。Graham 角色文件主要是提示；阈值/原则不是单独执行的 Graham 估值算法。

`blend_signals` 对非弃权 signal 按模型权重求带符号均值；中性票仍计分母。long-only 分析师的悲观意见可以降低持有但不能产生/加强空头证据；按 long_only/long_short/dollar_neutral 归一化到 gross_target，dollar_neutral 缺任一边则空仓。源码明确这不是将 conviction 校准成预期收益，也没有自动按不同预测时长缩放。

`apply_limits` 先验证权重与限额有限；普通模式逐票按绝对仓位上限截断，再超过总绝对敞口则按比例缩小；删除的敞口留现金，不重新分配。保留比例模式统一按最严格单票比例缩小，再按 gross 缩小，输出每次 `ClampEvent`。这些是模型无法辩论覆盖的确定性硬限制，但当前已读硬限制主要就是单票和总绝对敞口，不能包装成含行业/相关性/流动性/回撤/保证金的完整风险体系。

`assess_fund` 聚合策略权重、套硬限额并记录原始/final 权重；`execute_decision` 要求执行 session 晚于原始 as_of，必要时以 clock.previous 重评，再用精确执行时点 marks/权益转整数股数，检查预期仓位限额后调用 broker。`build_orders` 目标中缺席的已有持仓视为零并关闭，先卖后买。这里只读源码，没有调用 broker。成本模型只含每边半价差和每股手续费（默认 5bps、$0.005/股），明确尚不含市场冲击，不是容量模型。

**具体可复用项。** `apply_limits` 与带 before/after 的 ClampEvent，可移植为标准库 dataclass/dict 函数，接在模型决策参考之后；弃权与真正中性分离，防失败变成正常中性意见；prompt/snapshot hash 缓存和原始响应留档契约；assess/execute 时间分离可转成“研究时点/评估时点”隔离；ledger 的逐条 prev_hash、自身 hash、按序重放是可借鉴的审计结构。

**不可直接复用项与验证边界。** 信心 0–100 是模型自报观点强度；Graham 提示的 90–100“每项标准清晰满足”不是对未来事件频率的概率。将很小的唯一非零观点归一化到固定 gross_target 可能仍消耗完整目标敞口；硬限额会截断但不证明配置合理。`build_orders` 的纯函数依赖上游已验证 marks/equity，并不自行保护所有输入。

FD 客户端确实传 `filing_date_lte`，而不是仅 report_period；但本地方法只信任服务端返回，所读处未再次逐行校验日期。snapshot 明确接受 sector/industry 为 latest 的 PIT 近似；分钟研究又将财报 cutoff 降到日期，所以同日盘后披露/修订和日内可知时间必须单独核验。blind prompts 隐去 ticker/日期等只能缓解污染，不能证明模型无法识别公司。

ledger 的 `replay(full=True)` 会逐条验证内容 hash/prev_hash；默认快速模式可从 checkpoint 开始，而 `_trusted_checkpoint` 主要核对最后记录 hash，没有重放验证 checkpoint 内现金/仓位与整段历史一致。它有 rewind 保留 superseded 记录。hash 链也没有外部锚定/签名：有写权限者整链重算仍可改变历史。故可以说“可检测未经重算的改动”，不能称不可篡改审计证明。paper ledger 不证明实盘成交或收益。
