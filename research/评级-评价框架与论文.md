## 19. ForecastBench

**名称与链接／类别：** [官方仓库](https://github.com/forecastingresearch/forecastbench)、[论文](https://arxiv.org/abs/2409.19839)、[官方文档](https://forecastbench.org/docs/)。类别：前瞻题库、裁决和统一概率评价。**代码 B／方法 A／E2**。

**实际阅读：** 固定 commit 下 [leaderboard/main.py](https://github.com/forecastingresearch/forecastbench/blob/e8d3c94f9b7f424bbd1205007db08cf2950a45a3/src/leaderboard/main.py) 的评分段（2297–2476）、题级 bootstrap 段与 Brier Index 段（2940–2995）；[question_sampling/_prepare.py](https://github.com/forecastingresearch/forecastbench/blob/e8d3c94f9b7f424bbd1205007db08cf2950a45a3/src/question_sampling/_prepare.py)；[resolve/_prepare.py](https://github.com/forecastingresearch/forecastbench/blob/e8d3c94f9b7f424bbd1205007db08cf2950a45a3/src/resolve/_prepare.py)；根 LICENSE、leaderboard requirements 和文档。论文全文已保存，评级核心依据上述具体评分源码。

**输入→处理→输出：** 题号／来源／方向／预测到期日／裁决日／概率及 outcome → 验证概率范围与题目日期，按题合并裁决 → 原始 Brier、减题目固定效应的分数、聚合榜单和不确定性。`brier_score` 确实计算 `(forecast-resolved_to)**2`。`two_way_fixed_effects` 对适用题型拟合 `brier_score ~ 1 | question_pk + model_pk`，剔除若干 dummy、external submission 和过老模型后估题目难度；市场题亦可采用市场 Brier 作为难度代理。`brier_skill_score` 在这个版本中是 **参考 Brier 减本模型 Brier 的差**，不能按名字误读成通常的 `1-BS/BS_ref` 比率。

**时间与切分核验：** sampling 按 forecast due date、close／resolution date 剔除过早、过晚结算市场题；prepare 将 dataset 裁决日限制在题集合法日期内，并检查概率在 [0,1]、非空。它为前瞻轮次提供契约；本轮没有核验外部参赛者上传时间的完整强制机制，也没有审计所有数据源是否使用历史 vintage。不能把题库时间门槛解释成任意 Agent 内部检索都无泄漏。

**可复用清单：** `brier_score`；同题参考模型差值；`_question_level_bootstrap` 的按题重采样思路（同题多期限／多预测不能当独立样本）；问题主键、forecast due 与 resolution 日期分离的契约；缺失预测披露／插补审计；`rescale_difficulty_adjusted_brier` 与 `apply_brier_index_transform` 的明确版本化定义。后者先平移难度分数使 always-0.5 基线均值为 0.25，再作 `(1-sqrt(rescaled_score))*100`，并非原始 Brier 乘百分比。

**不可直接复用：** 整个榜单脚本混合 I/O、云存储、模型身份、展示与统计，导入依赖较多；本地少量假设不够稳健估计双固定效应。不要为了本地小样本制造“官方 Brier Index”；同一原始 Brier 也不能跨不同问题难度直接排名。固定效应依赖比较群体与版本，难度调整结果不能当单条事件的固有概率质量。

**许可／依赖：** 根 MIT 已读（保留版权与许可文本）；模型不存在统一许可，LLM API 各自适用条款；市场／经济数据和第三方题目许可未逐源核实，MIT 不替数据授权。评分脚本依赖 pandas、numpy／scipy、pyfixest、joblib；完整流程还含 Google Cloud、gcsfs、GitPython、Slack、pandera 等。基础 Brier 可按数学定义独立用标准库实现，不必携入完整依赖树。

**效果与边界：** 它提供持续前瞻比较基础设施，不是提升概率的预测器。不同轮次、来源、市场／群体信息可见性和缺失题处理都会改变比较。所有榜单数值及误差条本轮未重算。

**本地接入点与理由：** 放在 `scripts/journal.py` 的 `stats`／未来独立 evaluation 层：保存原始逐题损失、同题市场基线和样本数，再增按题 bootstrap。让 claims／hypotheses 登记明确事件、概率、as_of、裁决标准与期限。方法 A 是直接补评价缺口；代码 B 是实际实现可抽取但整合成本较高。**剩余核验：** 源码运行版本、数据许可、插补阈值、实际 deadline 强制、依赖兼容和本地小样本置信区间。

**输入→处理→输出：** 时间索引 OHLCV、策略信号、持仓与现金、手续费／滑点／流动性配置 → 排队至下一交易日开盘执行／可选 same_close，估价与成本记账 → 交易记录、净值、年化收益／波动／Sharpe／Sortino／回撤及外部 LLM 成本。`prior_volume_stats` 严格使用 `d < date` 的历史量；`apply_slippage` 为固定百分比加参与率平方项；`apply_liquidity_cap` 按历史平均量封顶。

**切分与执行核验：** `finsaber_bt.py:163–179` 将训练窗截止于测试开始日前一天。XGBoost 标签是 `close.pct_change().shift(-1)>0`，去 NA 后训练；仅这一局部标签代码不能证明所有策略调参／选股无泄漏。ISO 框架每天先执行 pending，再调用 `strategy.on_data`，默认 `next_open`；支持 same_close，这要求信号形成／提交时点与收盘撮合的一致性。末日强制按 close 清仓且 `force=True` 绕过流动性 cap，属于实验收尾假设，不能当实际成交保证。默认滑点和流动性限制均可为零，应明确报告配置。metrics 对非零收益少于 5 个、零波动或非有限结果返回 0 的 Sharpe／Sortino；这混合了“无足够证据”和实际零风险调整收益，接入时应另带有效性／样本数标记。

**重要边界：** 两个路径都存在依据全期尾部数据识别退市的启发式。ISO 的 258–264 行、BT 的 195–209 行通过最终可用日期与期末相比判断“疑似退市”，随后删去最后 7 天。这不是已验证的点时退市公告数据；可能把缺数据／交易日历问题当退市，也使用了历史当时未必知道的终点信息。策略还能拿到 helper／data_loader；本轮未发现一个可证明策略无法访问未来数据的权限沙箱。不能宣称框架彻底消除前视。

**可复用清单：** 成本纯函数、先信号后成交契约、`signal_date` 与 `execution_date` 分栏、reject reason、LLM 外部成本与交易费用分账、历史流动性 cap、多时期与多标的比较的实验设计。**不直接复用：** 全量策略／Agent、未经点时核验的数据、退市截断逻辑和“最佳策略”结论；XGBoost 输出后阈值化买卖不证明该分数已校准为上涨概率。

**许可／依赖：** 主框架 Apache-2.0 已读；迁入需保留对应许可与 notice 要求，子目录含第三方 FinMem／FinAgent，不把根许可泛化为全部外部模型／素材许可。包依赖 backtrader、pandas、numpy、pyarrow、matplotlib、rich 等；research extra 含 xgboost／statsmodels／datasets。模型 API 权限和金融数据（含新闻、财报、价格）条款未逐源核实。

**效果与边界：** 原论文扩大时期／标的后的结果可以反驳仅靠少量牛市窗口评估，但不能推导所有 LLM 分析无效；当前 main 的改进也不能倒推论文实验已使用相同成本。未运行任何旧／新版结果。

**本地接入点与理由：** 暂用于 journal 之后的离线“建议→模拟动作→成本后结果”附加评估，不侵入证据判真与概率评分；优先自行按数学定义实现成本小函数和时间字段。B/B 反映局部代码可用、方法需要交易场景与数据前提。**剩余核验：** reproduce 精确代码、调整价／退市支付／幸存者股票池、所有数据发布时间、策略超参选择、API 成本账本和 forced liquidation 的敏感性。

**时间与评分核验：** `CutoffEnforcer.filter` 用 `released_at <= as_of`，空值或整列缺失则回退 `timestamp <= as_of`，源码也承认对有发布滞后的官方数据会产生乐观偏差。不能把“timestamp 早于 cutoff”当真正历史可得；仅有该筛选不保存修订 vintage，也不能拦截模型参数或自行联网泄漏。context 文档查询按 publication_date 过滤，仍依赖该字段与正文版本正确。

Brier 是二元均方误差，RPS 用类别累计概率差的平方和（不除 K−1），适用于**有序类别**，不能把纯名义类别任意排序后照用。`_crps_for_prediction` 直接把 `quantiles.values()` 排序后当等权 ensemble 交给 properscoring；忽略 quantile level。细而均匀的分位网格可近似，非均匀网格（如 0.01、0.5、0.99）等权处理改变了分布含义，不能声称精确 CRPS。批量 Brier/RPS helper 的值域校验也不完整，应通过 payload 契约或接入侧严格校验。evaluation 模块的 protected window 靠规范不改动，运行次数限制仅在传入 EvalTracker 时生效；省略 tracker 会无条件运行，所以不能称为强制隔离的隐藏测试集。

**可复用清单：** 独立参考接口的设计：as_of data view、任务类型决定 score、二元／有序类别／连续分布分开、保留逐预测分数与 skipped origins、release time 与 observation time 分离。**不可直接复用：** 根许可未澄清前不复制代码；时间筛选不能充当隔离安全边界；quantile CRPS 应换成正确分位积分／适当权重算法，修订数据需要 vintage。

**许可／依赖：重要冲突。** 包 pyproject 写 `license = "MIT"`，但根 LICENSE.md 是 **Vector Institute License**，第 5 行规定 Work 只能由 Academic Entities／Sponsors／Partners 访问使用，学术实体需批准，第 24 行限制许可并明确禁止 Sell。没有取得授予本地插件的独立 MIT 授权，不能据元数据认定宽松开源或商用可用；此处不是法律意见，是可核实的文件冲突。应向权利人确认范围和优先条款。依赖 pandas、pydantic、properscoring、fredapi、stats-can、yfinance；可选 Agent／LLM／数值模型依赖 ADK、aieng-agents、Langfuse、LiteLLM、Darts、LightGBM 等。第三方数据、模型 API 权利未核实。

## 22. Temporal Leakage in Search-Engine Date-Filtered Web Retrieval（ACL 2026 short 65）

**名称与链接／类别：** [ACL 官方页](https://aclanthology.org/2026.acl-short.65/)、[原文 PDF](https://aclanthology.org/2026.acl-short.65.pdf)、[作者审计代码](https://github.com/theolivecode/WebDataLeakageAudit)。类别：历史检索时间污染审计。**代码 C／方法 A／E2**。

**实际阅读：** 论文 §3 方法、§4 结果、limitations 与附录 rubric；固定 commit [leakage_judge.py](https://github.com/theolivecode/WebDataLeakageAudit/blob/02ad57569ebe963efdcf0c28de6a8543ae3b0a1e/leakage_judge.py)、[prompts.py](https://github.com/theolivecode/WebDataLeakageAudit/blob/02ad57569ebe963efdcf0c28de6a8543ae3b0a1e/prompts.py)、MIT LICENSE。

**输入→处理→输出：** 已裁决题、开题 cutoff、搜索结果正文与正确答案 → judge 判断 post-cutoff 内容并按 0–4 rubric 评分 → `contains_post_cutoff_info`、`leakage_score` 和具体 reasoning。官方代码 `is_valid_schema` 检查字段类型，明确拒绝 bool 充当 int、分数需在 0–4；NDJSON 可断点跳过已处理 question-url。**但 `call_llm_and_extract_json_tags` 第 21 行直接 `raise NotImplementedError`**，不是可运行的完整审计后端，所以给 C，局部 schema／提示可参考。

**方法与证据边界：** 393 个 Metaculus 历史题，DDG 有效 389 题；每题 10–20 次查询、约 100 URL，cutoff 为开题日；长文用 MMR 取相关片段。Google 38,879 URL、DDG 34,454 URL，至少一个严重信号（≥3）的题比例分别 71.0%／81.2%，直接答案 41.0%／54.8%。不是所有网页比例，也不能泛化为所有任务的错误率。judge 为 gpt-oss-120b，134 篇人工共识标注验证，合并 0/1 后 exact agreement 76.1%、QWK 0.85；该人工集合在提示迭代中用于验证，不能当完全独立盲测。

下游只选 Google 文档中**至少有一篇 score-4 的 2025 二元题，共 93 题**；clean Brier 0.242、strong-to-direct 0.108（摘要约 0.10）、score-4-only 0.129。不能脱离选样条件引用为所有预测的平均收益。正文四类机制：直接页面更新、相关内容模块、错误时间元数据、缺席信号。排除更新文本仍可能删除原先错误而有用的旧内容，无法还原历史信息集。论文 judge 和 forecaster 使用同一模型，作者承认可能存在共享解释偏差；也没有实测 Wayback／冻结快照等缓解方案，所以该研究不能为某一种修复的效果背书。

**可复用清单：** 0–4 时间污染标签、逐段指出日期与证据、按题／URL 留审计记录；人工校验 judge；原始正文 hash／抓取时点／公开时点和 cutoff 分栏。**不可直接复用：** 事后 judge 提示含正确答案，只能位于裁决隔离后的审计流程；不得注入实时预测提示。LLM 标签不是证明文本干净，缺省 `not flagged` 不等于无泄漏。

**许可／依赖：** 代码 MIT，脚本基本为标准库但缺 LLM transport；模型／推理服务条款未核，网页正文与 Metaculus 数据许可未由 MIT 覆盖。**接入点与理由：** 扩展本地 `check_claims` 的时间证据字段及独立回放审计报告；历史语料优先冻结快照并记录版本，再用 rubric 找显式污染。C/A 反映实现缺后端、方法直接相关。**剩余核验：** 可用模型后端、独立人标集合、跨金融／多语网页外推、取片段遗漏、快照检索排序偏差与数据权利。

**名称与链接／类别：** [arXiv](https://arxiv.org/abs/2506.00723)、[PDF](https://arxiv.org/pdf/2506.00723)。类别：评价方法批评。**代码 N／方法 A／E2**。

**许可／依赖／效果：** 理论建议无需搬用代码；文章可访问不等于全部文字／图表获任意再分发授权，本轮未核论文重用许可。底层模型、原始数据及示例软件许可未统一核实。案例和理论分析提供审计依据，不是新系统提升成绩的实验。

**接入点与理由：** 研究计划／假设登记阶段增加 `question_created_at`、`all_outcomes_resolvable_by`、model release、crowd-visible、correlated-event group；回放与实时评估分开。方法 A 对本地可检验研究最直接。**剩余核验：** 引用案例是否适用于我们实际题集、事件簇定义、实时前瞻样本、统计检验设计；不要机械照搬论文样本比例。

## 24. Gneiting & Raftery（2007）：Strictly Proper Scoring Rules, Prediction, and Estimation

**名称与链接／类别：** [DOI](https://doi.org/10.1198/016214506000001437)、[作者 PDF](https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jasa.pdf)。类别：概率评分理论。**代码 N／方法 A／E2**。

**实际阅读：** 20 页论文正文 §2 定义／表征、二元评分、连续分布 CRPS、分位数／区间及应用讨论。理论无本轮适用代码，不强行为 N 补一个第三方库。

**输入→处理→输出：** 报告的预测分布 P 与真实实现值 y → 严格适当 score → 单次评价及分布下的期望准则。正文使用 **reward orientation（越大越好）**，定义 `S(Q,Q) >= S(P,Q)`，唯一最大处在 P=Q。本地常用 Brier loss／CRPS loss 是取负后的方向，必须记录 `lower_is_better`，不能照抄符号反转排名。CRPS loss 可写成 `E|X-y| - 0.5 E|X-X'|`；严格适当性有相应分布类／有限一阶矩条件。

**可复用清单：** 二元 Brier、log loss，连续 CRPS、分位／区间评分的选择依据；明确预测对象、单位、归一化和方向；校准与 sharpness 同时考虑；同题、同信息预算的公平比较。概率 0／1 对数损失可能无穷，若工程作 epsilon 截断必须声明阈值，不能不披露改写评分。

**不可直接复用与边界：** 不生成概率、不保证校准、不解决信息泄漏或盈利。严格适当是对真实分布的**期望激励**，不是一条题／有限样本上的准确性证明；不能凭单次命中说 90% 比 60% 好。论文跨验证／随机分折讨论不自动适用于有时间依赖的事件预测，不应拿 random-fold 替代时间前推校准。CRPS 有目标变量单位，不同单位连续任务需事先定归一化基线才能汇总。

**许可／依赖／效果：** 理论定义可据其独立实现，本文非代码交付，代码／模型依赖不适用；文章文本／图表重分发条款未核。论文给数学性质和天气预测案例，不证明我们的未来事件概率经过校准。

**接入点与理由：** 本地 journal 的评分规范文件、score metadata 和测试参照；将命中率保留为辅助指标，原始概率 proper score 为主。方法 A 是所有概率评价的基础。**剩余核验：** 事件编码、二元 Brier 与多类 Brier 的因子差、缺失／作废样本、log loss 端点及连续分布积分实现。

## 25. On Calibration of Modern Neural Networks（1706.04599）

**名称与链接／类别：** [论文](https://arxiv.org/abs/1706.04599)、[作者实现](https://github.com/gpleiss/temperature_scaling)。类别：分类置信度后处理。**代码 B／方法 B／E2**。

**实际阅读：** 论文 §4（温度缩放、校准数据和同分布假设）、§5 与 ECE 局限；固定 commit [temperature_scaling.py](https://github.com/gpleiss/temperature_scaling/blob/ce1154ec7d5235eee046f28875c3dd8421f11d45/temperature_scaling.py) 全文、train.py 的训练／验证划分、README／MIT LICENSE。

**输入→处理→输出：** 已训练分类器的**原始 logits**、独立验证样本和标签 → 在验证集最小化 cross-entropy／NLL 拟合单个 T，作 softmax(z/T) → 校准后类别概率。代码 `ModelWithTemperature` 包装模型，`set_temperature` 缓存验证 logits，LBFGS 拟合，切 eval 模式防 BatchNorm 统计改变，随后恢复模式。`_ECELoss` 取最大 softmax 概率与分类命中率，默认 15 个等宽置信区间。

**切分与数值边界：** 作者 train 示例将 CIFAR 训练集随机留出验证集，适用于论文图像／文档分类的同分布设定；论文 §4 明确假设 train／validation／test 同分布。对本地时间事件，必须按时间使用已裁决旧样本拟合 T，后续样本独立评估，不能在测试题或未来结算标签上拟合。论文要求 **T>0** 才保留 argmax；作者实现用未约束的 `nn.Parameter`，LBFGS 没有显式正值约束，接入时应改为 log-temperature 等正参数化。代码强制 `.cuda()`，不能直接进标准库轻量插件。作者 README 首段还明确标记仓库已停止维护，原为 PyTorch 0.3 演示，不能当现代独立包直接接入。

**可复用清单：** 标量温度缩放的数学设计、验证集 NLL 目标、校准前后同题报告、可靠性图／分箱诊断。**不可直接复用：** 把 Agent 自述 confidence、生成 token softmax 或“观点人数”当分类 logits；温度缩放不会修正错误排序／信息不足，也不能校正所有来源偏差。top-label ECE 不等于每个事件的 P(Yes) 校准，二元事件须按 P(Yes) 与 outcome 分箱。ECE 对分箱／样本量敏感，不能仅优化 ECE 宣称改善全部概率质量。

**许可／依赖／效果：** 作者代码 MIT 已读；依赖 PyTorch，demo／训练还含 torchvision／CUDA，老示例兼容性未运行。模型权重和 CIFAR 等数据授权另行核实，代码 MIT 不覆盖全部。论文在多种图像／NLP 分类器上报告温度缩放有效，不是跨领域 LLM 未来事件校准实证。

**接入点与理由：** 在积累足够已裁决、同定义、同模型版本的假设后，增离线 calibration 工具与 calibration_version；实时概率保留 raw／calibrated 两列。B/B 因实现具体但需适配且场景前提强。**剩余核验：** 本地样本量／漂移、分来源分层校准、正值约束、NLL／Brier 外样本比较，及更合适的 Platt／isotonic 基线。

## 26. CruxBench: A Benchmark of Information Discovery

**名称与链接／类别：** [论文](https://arxiv.org/abs/2609.35879)、[官方代码](https://github.com/ai-prophet/cruxbench)。类别：研究子问题发现与事后信息价值评价。**代码 C／方法 A／E2**。

**实际阅读：** 本地 v1 36 页，§2 VOI 与估计、§3 构造／时间／代理、§4 比较与局限 §5；固定 commit [src/metrics.py](https://github.com/ai-prophet/cruxbench/blob/c036b3cd94881dc9efba448b7c02594db1b408fd/src/metrics.py)、step1_retrieve、step2_generate、step3b_verify 的时间逻辑、README、requirements；源码已保存而未执行。完整 commit 源码归档的根目录未见 LICENSE／LICENSE.md／LICENSE.txt，README 也未给授予条款，故不能按“GitHub 公开”直接复用。

**输入→处理→输出：** 目标二元问题＋起点前标准新闻集 → 模型提一个窗口内可裁决的 crux → 独立 resolver／timestamp verifier 裁决并对齐 public evidence time → 对市场 Yes 价格取事件前后均价 → 计算 Bernoulli KL（bits）和按模型总体平均。理论 VOI 为 `H(p)-E[H(P')]`；单次历史只观察一条分支，没有 q 与反事实 posterior，**单条 crux 的期望 VOI 不可识别**。论文改估总体 VOI，不能把单条实际 KL 标成其已证实的预期信息收益。

**评分与时间源码核验：** `before_after_prices` 用 W 小时 rolling 均价与负向 shift 构造前／后窗；`pivot_hour` 取严格早于裁决时刻的整点；`kl_bernoulli` 用 `KL(p_after || p_before)`，epsilon=1e-9；读取价格先小时重采样并 ffill，缺数据长段的处理需另审。step1 AskNews 明确传起止 timestamp；step2 验证 subquestion 截止日不晚于 window end，使用 ultimate 结束前 3 天缓冲。step3b 的 No 应于自身 deadline 才定，除非出现不可逆、绑定性的约束；提示禁止用后来没发生来倒推当时不可能。这一设计可借鉴，但提示是软约束，仍需核输出与证据。

**实证与边界：** 293 个目标来自 2026-03-25 Polymarket 快照，排除了体育／crypto／天气，并选流动性／不确定性达标市场；每题一个 30 日窗口。生成禁 web search，用最多 10 篇窗口前 AskNews 新闻，起点不早于 2025-09-01；不同模型训练信息仍不对称。未裁决 crux 记零，随机时点 baseline 与事后最大 KL oracle 同时报告；oracle 只是事后上限。8 个模型的显著性星号是**未作多重比较修正的单侧 paired t-test**，不能夸大窄幅领先。

正文承认市场价格是概率代理，噪声／同期别的消息都影响变化，不能把 KL 因果归于 crux。后续“提供 crux 及其未来答案”改善目标预测的实验**有意给未来信息**，用来研究答案贡献，非可部署起点预测策略。论文仍是 retrospective，不应称本轮成绩已通过实时前瞻抗污染检验。仅基于市场变动的 VOI 也不同于本地投资动作的净效用价值。

**可复用清单：** 研究 plan 中强制具体子问题、裁决来源、截止时间、支持／反对方向和更新条件；No 的判定时点规范；事后评估未裁决记零避免选择性删除；随机时点对照、事件前后窗敏感性、价格／文本证据版本。**不可直接复用：** 未许可的代码与数据文件；把市场涨跌等同于真实因果信息价值；把总体 VOI 点估计当单条 research question 的确定排名。

**许可／依赖：** 仓库许可未明确是代码 C 的主要原因；方法公式可根据论文独立实现，保留引用。依赖 numpy／pandas、模型 SDK、多 provider、AskNews、Polymarket 与部分链上 RPC。模型、AskNews 新闻及市场数据再使用条款未核，论文开放可读不等于整包新闻可商用再分发。

**本地接入点与理由：** 对研究 `plan` 加 crux 契约，把“还缺什么证据”转为有期限的可裁决子问题；journal 后续记录答案公开时刻、目标概率改变和实际研究成本。先以人工明确 reason 的研究路由使用，不为了缺市场流动性的股票问题硬造 KL。方法 A 直接补研究问题选择缺口；代码 C 因许可未核及外部依赖。**剩余核验：** 许可授权、价格构造与缺值、resolver 原始 search logs（README 说明发布版省略）、时间误差、混杂事件、实时前瞻验证、多重检验与总体估计方差。
