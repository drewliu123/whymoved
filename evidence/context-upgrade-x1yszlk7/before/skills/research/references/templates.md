# 从问题选择研究方法

类型描述对象，任务决定本轮要回答什么。按问题选必要检查项，不机械跑完所有角度。

## 先写问题契约

`plan.json` 至少记录：

- `question`、`type`（event_pricing / asset / theme / actor）、`task`、`entity`。
- `as_of`（带时区的截点）、`historical`、研究期间与比较基准。
- `decision_needed`：用户读完应能判断什么；例如“区分公司特有下跌与板块共同下跌”。
- `prior_judgment`：已有判断或用户当前基准；没有就写明首次研究。
- `hypotheses`：带稳定`id`与`explanation`的候选解释，各自支持/否定它的观察。id贯穿计划、检验与报告，不随结论改变。
- `queries`：问题、检索词、来源职责、时间窗口、预期用途及`test_ids`。背景查询可用空列表；每个区分检验至少有一条查询覆盖。年份、财报期、会议日、地区、单位都是合法限定词。
- `budget`：本轮检索与补查预算；`stop_condition`：问题得到回答，或关键缺口无法在预算内补齐。
- `parent_run_id`：仅更新任务填写。比较口径需要显式记录 period / unit / scope。

常见任务：变化解释、预期比较、机制研究、承诺核对、更新跟踪。混合问题选一个主任务，其他作为支撑。仅当歧义会改变研究对象或答案时澄清；其余采用合理范围并告诉用户。

新plan另写`analysis_version: 1`与`research_design`，研究者明确选择六种`question_kind`之一：change_explanation、operating_outlook、valuation、event_forecast、theme_transmission、commitment_check。`analysis_contract.py route <question_kind>`按该选择返回method、必需输入与模型要求，不自动语义分类。research_design记录question_kind / method / rationale / baseline / price_relevance / mechanism_chain / discrimination_tests；链条至少两个变量。每个检验有id / observe / source / by / outcomes，outcomes至少给两个不同解释各自不同的预测（hypothesis_id / prediction）。除commitment_check外须竞争解释与检验；承诺核对可无竞争检验，但仍记录解释。字段示例与精确模型输入见[analysis-methods.md](analysis-methods.md)。

选择price_relevance时判断本轮是否需要回答价格反映了什么。true在报告中必须评估市场预期或明确记录缺失；valuation必须true。只问经营/公开承诺等非价格问题可false并写不适用理由。将预期矩阵与参数放附录，正文保留判断、机制和关键结果。

检索同时覆盖：核心对象、支持主解释的证据、最强竞争解释、具体未决数字/条款。不要只搜结论同义词。中文社区按对象另写中文词，名称冲突加行业或代码限定。

涉及预期的任务按[expectations.md](expectations.md)，在现有queries中写明“谁对哪一期什么指标/结果、在何事前截点的预期”，以及是否需要同一期历史修订、分布或跨市场比较。没有符合口径的预期材料时记录缺口；不得用当前报价、模型nowcast或公司指引填充未知的历史调查共识。

## event_pricing：先读清合约，再研究驱动

| 检查项 | 研究动作与交付 |
|---|---|
| 合约身份 | 精确市场/选项、YES含义、窗口、时区、裁决来源、默认状态、延期/取消/未列结果 |
| 当前状态 | 哪些合格事件已经发生，哪些只是意向；事件时间与报道时间分开 |
| 主要驱动 | 官方数据、决策者权限、条件频率；同条件样本与无条件历史频率分开 |
| 市场基准 | 选项/token、报价时刻、bid/ask/last/参考价、深度与费用；异步报价不相减成错价 |
| 判断 | 独立概率若存在，记录其方法和冻结输入；没有校准依据时给定性判断，不制造价差 |
| 下一观察 | 哪个数据或裁决会改变情景权重；明确观察时间/来源 |

旧 `polymarket.py event --json` 返回Gamma第一选项参考值，缺token、报价时间和盘口深度，不能单独作为严格v2可成交价格证据。需要补原API/订单簿与选项映射。市场价格、研究判断、登记概率是三项不同内容。

## asset：先量化变化，再解释

| 检查项 | 研究动作与交付 |
|---|---|
| 实际表现 | 明确起止、交易日、收盘/复权/总回报；同期指数、行业和可比资产 |
| 事件与预期 | 公告/数据时间线、之前预期与实际差异、估值假设变化 |
| 经营机制 | 收入量价、利润率与利润额、现金回收、资本需求；金额用可重算公式连接 |
| 归因比较 | 公司特有、行业共同、利率/风险偏好等竞争解释；时间先后与共变不自动证明因果 |
| 下一验证 | 哪项经营或预期数据能区分解释；没有归因输入时明确回答到哪里 |

一个有趣的财务线索不能替代“为什么跌”。若任务只问业务兑现，价格基准可不展开。数字口径相同才作同比/环比。

## theme：找到价值在哪一段兑现

画出需求 → 项目与采购 → 订单/backlog → 交付验收 → 收入 → 利润 → 现金的链条，标出每段已观察、推断或缺失。优先研究最可能阻断传导的环节。

核对价格/量/组合/成本、取消延期、产能与利用率；区分存量和流量、AI和广义数据中心、分部与全公司。并购/汇率/分部变化先对账，分部利润排除的Corporate费用写近表格。不能用平均利润率代替新增贡献率，用backlog/季度收入当锁定季度数。

比较受益者需客户侧与竞争者资料。只取得一家材料时给该环节的研究判断，不声称选出全行业赢家。半年展望按半年加权金额检验，单季不能代替半年。

## actor：把承诺和兑现配对

记录原话、时间、场合、版本、条件、金额、时限、行动权限和裁决标准；与实际行动、交付和结果一一对照。区分计划、批准、投入、上线、利用和回报。

管理层对变化原因的解释标为自述，另找独立核查。分类修订、延期和取消分开。ROI要匹配投入批次、期间、现金与收益；披露不足不能推断回报差。只研究公开可观察的激励和权限，不猜测个人内心动机。

## 更新任务

读旧run的原始报告、证据和比较口径，写出：新增事实、原证据修订/冲突、主判断是否改变、改变原因、下一观察。结构diff只比较字段，不理解经济含义；旧来源ID稳定复用，新来源用新ID。没有改变判断的新信息可以直接交付no_change_reason，避免为更新而凑发现。
