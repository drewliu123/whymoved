# 投研助手端到端改造方案 v2

日期：2026-10-31  
状态：供产品决策与后续 GitHub Issue 使用的方案；未实现、未发布。  
方法依据：[四类研究方法审查](touyan-four-type-research-review-20261031.md)  
历史版本：[第一版方案](touyan-end-to-end-plan-20261031.md)，保留原文。

## 1. 产品定位与预期

用户提出一个投研问题，Agent 交付一份直接回答问题、解释关键机制、给出当前判断和更新条件的研究结果。文字、HTML 和图片是同一份研究内容的不同呈现。

四类研究都纳入方法设计与首轮案例验证；数据接入按已验证的子类型逐步开放。覆盖四类不代表同时支持所有市场、制度和资产。例如 asset 首轮验证股票，其他资产必须完成专属方法和资料验证后才能声明支持。

首版优先改善：问题回答、信息重要性、机制解释、数值正确性和可读性。预测胜率、超额收益与全面自动化没有当前实证保证。

## 2. 相比 v1 的六项调整

| v1 | v2 |
|---|---|
| 首版先做美股页面与数据链 | 先验证四类研究方法，再实现共通交付；具体数据适配分批开放 |
| 四类主要对应检索角度 | 四类分别规定必须完成的分析与验收 |
| 来源取齐后综合写作 | 先定义基准、候选解释和关键缺口，再按改变判断的价值取证 |
| market / independent 二选一 | 分开市场基准、研究初判和参考市场后的最终判断 |
| 一套 report 内容结构承载全部 | 通用骨架＋类型专属分析数据＋任务相关页面组件 |
| 质量门槛以证据与页面检查为主 | 分开事实、计算、机制、预测、阅读价值及成本／完成率 |

## 3. 用户入口：对象、任务与交付深度

对象保留 event_pricing / asset / theme / actor，但允许主次组合；新增任务维度：现状速览、变化解释、预期比较、前瞻预测、持续跟踪。

| 用户问题 | 必须先回答 | 主要研究链 | 适合交付 |
|---|---|---|---|
| NVDA 最近为什么跌？ | 跌了多少，相比什么，主要候选解释是什么？ | asset＋变化解释 | 相对表现图、事件线、经营与预期分歧 |
| 某 Polymarket 合约合理吗？ | 合约怎样结算，关键驱动是什么，研究与市场有何差异？ | event_pricing＋预期比较／预测 | 事件卡、结果分布、更新节点 |
| AI 用电会让哪些环节受益？ | 需求如何形成，瓶颈在哪，谁能取得利润？ | theme＋机制分析 | 传导图、敞口矩阵、经济量级与验证指标 |
| 某机构的表态可靠吗？ | 有什么权限，说法有何条件，实际做了什么？ | actor＋表态行动核对 | 时间线、条件与权限卡、兑现记录 |

简单问题直接短答；只有多段关系或数据比较需要时才生成报告。需要研究深度时明确本次模块及预算；来源失败不自动扩大调用规模。

## 4. 四套必须回答项

### event_pricing

- 事件契约：完整规则、来源、截止时间、时区与状态。
- 基准率／模型依据及适配性。
- 当时证据、关键驱动、条件关系、替代情景。
- 概率语义与一致性：互斥／穷尽／单调性。
- 同刻盘口与流动性；研究判断与市场比较分开。
- 下一节点、更新理由、真实结算和评分规则。

### asset

- 实际变化与恰当基准，时间和收益口径明确。
- 经营／供需驱动，数字怎样影响经济价值。
- 预期与实际比较；公司指引不冒充市场共识。
- 当前定价与情景的联系，按问题决定是否需要估值。
- 竞争解释、反方、失效条件与下一可观察指标。
- 资产子类型决定数据与模型；不套用统一财报模板。

### theme

- 可证伪命题、地区、期间与比较基准。
- 需求到交付、收入、利润和现金的传导。
- 约束、时滞、替代与价值归属。
- 分部／产品／合同敞口，区分已披露、估计、定性关联。
- 可重算的经济量级；关键假设不足时不给点估计。
- 冲突证据、失败路径与领先指标。

### actor

- 权限、治理、激励和制度约束。
- 原话的时间、场合与条件。
- 当时信息、实际行动、宣布与执行的区别。
- 表态、行动与结果的匹配及替代解释。
- 可观察边界、披露滞后与下一验证。
- 人物／机构作为其他研究视角时，避免重复整篇报告。

## 5. 一问到底的运行流程

1. **任务契约**：提取问题、用途、对象、时间、基准、输出偏好和必须回答项。
2. **研究设计**：选择专属方法，提出候选解释／情景；明确什么资料可能改变判断。
3. **能力与来源检查**：确认可访问资料、历史窗口、供应商与权限；记录失败原因。
4. **取证与数据归一**：官方／行情／预期／新闻行业／社区按需要并行；保存原文、时间、口径和来源关系。
5. **计算与模型**：脚本执行数值计算；区分观测、假设、估计。缺输入时停止对应计算。
6. **研究综合**：筛选重要变化，比较解释，说明判断、机制和关键反证。事件研究需要时记录盘口前初判。
7. **类型专属审查**：检查规则、口径、传导、权限和替代解释；有明确价值的缺口再定向补查。
8. **编辑与交付**：冻结内容，选择图表，生成文字／HTML／图片并检查。证据放可展开层，首屏直接回答问题。
9. **归档与更新**：报告归档；可选预测登记；保留版本和变更原因。持续跟踪需单独配置触发及执行能力。

社区引擎继续复用 Last 30 Days 的检索、去重、聚类和来源诊断。研究的参考类、制度、业务结构按需要使用更长历史，不能受最近 30 天限制。社区热度不作为事实可信度或经济重要性评分。

## 6. Agent 与程序分工

默认维持少量职责：

| 职责 | 产出 | 约束 |
|---|---|---|
| 主研究者 | 问题契约、研究计划、综合判断、最终编辑 | 对答案负责，不把子代理报告当事实证明 |
| 事实／数据取证 | 有出处的原文和数据、缺口与来源状态 | 不暗填默认数值，不跨时点补证据 |
| 社区取证 | 议题、代表原文、覆盖与失败状态 | T4 只支撑叙事、观点和调查线索 |
| 计算程序 | 指标、情景、概率约束、公式与输入记录 | 确定性计算；不负责凭空设经济假设 |
| 独立审查 | 关键错误、替代解释、需要补查或改判之处 | 按类型检查漏洞，不强行平衡多空篇幅 |
| 渲染程序 | HTML、Markdown、图片 | 消费冻结内容，不新增研究结论 |

综合与编辑先由主研究者分步骤完成。新增专门建模、多角色辩论或额外预测者，需有消融证据；以质量增量和成本决定是否保留。

## 7. 结构数据与产物契约

建议分成三层，字段名称在实施时按案例定稿：

- **通用研究骨架**：问题、截点、主判断、关键发现、支持、竞争解释、关键未知、更新条件、引用。
- **专属分析载荷**：事件契约／概率与盘口；资产指标／预期／情景；主题机制／敞口／经济量级；机构权限／表态／行动。
- **呈现计划**：短答、正文模块、图表声明、展开证据和导出偏好。

复用 v1 的 request / sources / claims / datasets / calculations / report / checks / manifest 概念。不要在案例未验证之前冻结大而全 schema。

共同规则：

- 每个图表绑定可检查的数据集；每个估计有假设和公式。
- 来源记录事件时间、发布时间、首次获取时间、文档版本及原文定位。
- 除 URL 去重，还记录同公告、同数据或同访谈的传播关系。
- 历史问答按证据可用时间过滤；该措施不能消除模型训练记忆，应另外做前瞻验证。
- 缺失与零分开；模块状态区分成功、部分完成、失败与不适用。
- 报告归档允许没有预测；换格式不重复登记；预测方法变更保留旧版本。
- 作者的内容相关性、来源可靠性和预测表现分别记录，不合并成少量命中率的单一等级。

## 8. 输出设计

所有报告的首屏回答四件事：**目前的判断、最重要的依据、对原问题的意义、下一项会改变判断的观察。**

| 类型 | 优先组件 | 只在数据适合时增加 |
|---|---|---|
| 事件 | 事件卡、驱动与规则、市场比较 | 概率轨迹、分布、条件情景 |
| 资产 | 实际变化、指标／预期对照、解释 | 相对表现图、利润／现金桥、估值敏感性 |
| 主题 | 机制图、断点、敞口矩阵 | 需求至利润量级分析、领先指标趋势 |
| 人物／机构 | 权限卡、条件性表态与行动对照 | 承诺兑现时间线、反应条件图 |

图表不为凑数量而生成。不同量纲用分图，不用双轴。机制图的连线区分证据支持与待检验推断。图片和 HTML 共享内容，图片需要可读的来源与截点；交互 HTML 同时有表格、键盘读取与打印支持。

表达层减少重复防御句：核心不确定性集中说明，关键判断带证据脚注，完整审计信息可展开。允许有根据的倾向判断，避免把每种解释写得同样重要。

## 9. 验收体系

| 层 | 主要检查 | 失败怎样处理 |
|---|---|---|
| 资料 | 来源、时点、原文支持、独立性 | 补证据、降级主张或标部分完成 |
| 计算 | 期间、单位、公式、概率约束 | 修正计算；不让错误数值进入渲染 |
| 研究 | 回答问题、机制、替代解释、关键反证 | 定向补查或修改判断 |
| 阅读 | 用户能否复述结论、理由、下一观察 | 调整排序、篇幅和图表 |
| 交付 | 内容一致、引用、页面、导出、归档 | 明确交付状态并保留失败记录 |
| 前瞻 | Brier／log loss、财务误差、主题里程碑 | 保留全部有效样本，按预定规则复盘 |
| 效率 | 成本、延迟、来源成功率、完成率 | 对照预算调整分工，不以调用数作成绩 |

基础门槛与偏好评分分开。虚构数字、未来证据泄漏、错误结算语义是严重问题，不能靠漂亮页面抵消。

原始插件、单研究者检索、新方法，以及是否加入审查／聚合，应在同题、同时点和同预算下比较。自动判定处理结构和计算，人评处理机制与阅读价值；预测按真实未来结果评价。开发案例与保留测试隔离，不能反复改同题后宣称泛化提高。

## 10. 新的阶段顺序

### P0：先完成四类内容验证

交付四套方法卡和 12 个开发案例定义；每类完成一个代表成品，其余覆盖反例与缺口。记录来源可用性和每项关键判断的依据。先验证“写什么、有什么用”，允许人工协调流程。

建议案例：

| 类型 | 正常任务 | 压力情形 | 部分完成／否决情形 |
|---|---|---|---|
| 事件 | 一个规则清楚的未来政策／财报合约 | 相关子市场或阈值结果 | 规则歧义、缺深度或延期 |
| 资产 | 近期下跌解释，复用 NVDA 材料作开发输入 | 业绩增长却低于预期 | 缺可靠预期或关键行情 |
| 主题 | AI 用电到设备订单／利润 | 需求兑现但利润被扩产稀释 | 敞口不足，主题无法量化 |
| 人物 | 央行条件表态到决策 | 管理层宣布与实际执行不同 | 13F 无法还原当前持仓 |

这些是案例设计，不是声称已经找到并跑完对应真实题目。事件实际选题要核实仍未结算与可访问性。

### P1：公共证据、计算与交付

从 P0 成品反推最小内容契约。实现时间／口径／来源状态、确定性计算、同源 HTML／Markdown／PNG、页面与归档检查。拆开报告保存与预测登记。

验收：四类代表成品保持内容一致；缺数据、计算失败、来源不可用有真实状态；重渲染不产生新预测记录。

### P2：类型专属分析自动化

事件先完成契约、盘口、概率语义和更新；股票先完成变化、财报与预期连接；主题先完成机制、敞口与量级；机构先完成权限、条件和行动。每个模块用已确认可访问的来源，分别通过保留案例。

资产子类型、国家／地区及付费数据逐项列支持矩阵。通用检索可接触不等于正式支持。

### P3：一问到底与回归

串联路由、取证、计算、综合、审查和输出。使用此前没参与设计的题目，比较旧版、简单检索基线和新链路。只有读者价值与研究质量确有改善，成本在可接受范围内，才宣称自动化路径成立。

### P4：持续跟踪与前瞻评估

先影子记录，再做触发式更新。保存预测提交时点、同刻市场基准、更新原因、取消与争议。积累足够独立事件后分析校准和相对成绩。是否增加更多 Agent 或资产子类型，由实际误差与用户需求决定。

阶段长度在数据依赖、开发能力和验收规模确定后估算，不把未经验证的时间表当承诺。

## 11. 下一阶段的工程交接边界

建议下一项实际工作为 P0 四类代表案例与方法卡验证，之后再形成实现 Issue。它属于本次方案的后续执行，本轮尚未开始。

本地方案是讨论材料；若采纳为工程需求，需同步到正确 GitHub 仓库和一个满足契约、AI Ready=Yes 的主 Issue；设计路径、AC、Owner、数据依赖与风险在 GitHub 明确。Issue／评论／push／PR 的写操作仍须用户授权。

本轮没有修改研究技能、脚本、作者库或正式预测账本；没有安装／运行外部 Agent 项目；没有完成四类效果实测。新增文档保留研究依据、方案变更和待验证项，以便做可审查的产品决策。
