## 1. 对上一版方案的评价

上一版适合作为交付工程的底稿，还不足以作为研究质量方案。它回答了怎样取资料、保存证据、生成 HTML，却没有充分回答：不同问题必须完成怎样的分析，才能产生有用的判断。

| 维度 | 当前评价 | 能合理预期什么 | 尚不能据此承诺什么 |
|---|---|---|---|
| 可追溯与多格式交付 | 方向较完整，尚未实现 | 同一内容生成文字、HTML、图片，数字可追溯 | 实际链路成功率、页面质量 |
| 回答用户问题 | 较旧版有改进，仍缺任务级验收 | 先回答变化、解释、下一观察 | 所有问题都能从固定角度得到好答案 |
| 研究深度 | 关键缺口 | 增加机制、预期差、反证可改善内容 | 仅靠增加综合／编辑 Agent 达到专业水平 |
| 四类适配 | 不充分 | 共享证据和输出基础设施 | 美股财报方法能直接处理选举、主题或监管 |
| 预测质量 | 尚无本产品实证 | 建立可复盘的概率记录 | 胜过市场、稳定校准或盈利 |
| 阅读价值 | 原则合理，有一张人工样例 | 信息排序、机制图与重点图表有望减少阅读负担 | 自动生成可以稳定复制样例质量 |

因此，我对预期质量的判断是：按原方案实施，最先改善的是阅读与交付；事实摘要可能更齐全，但深度与独立判断仍可能不稳定。只有补上类型专属方法和评测，才有理由期待持续提升。这里不给没有实测依据的质量分数。

真正要保留的产品目标是：用户得到一份能减少关键不确定性、改变下一步研究方向的答案。报告长度、Agent 数量、引用数量和图表数量都不是这个目标的替代指标。

## 2. 调研得到的共同结论

### 2.1 把四种能力分别评价

1. **找到正确资料**：来源是否适当、是否及时、是否真正支持主张。
2. **算对并解释**：口径一致，计算可复现，能说明数字为什么重要。
3. **形成研究判断**：连接驱动与结果，比较替代解释，指出判断成立的条件。
4. **预测未来**：问题可结算，概率经前瞻记录后评价校准与准确性。

FinanceBench、FinSearchComp 和 Finance Agent Benchmark 主要支持前两项的评测设计。[S1–S3] FinResearchBench 与 Deep FinResearch Bench 将报告结构、假设和深度纳入评价，但仍有自动评分、样本与时间控制方面的限制。[S6–S7] ForecastBench 则要求对未知结果作预测，不能用财务问答成绩替代。[S9]

### 2.2 完整的研究链

**问题与用途 → 当时可用的信息 → 基准 → 机制／模型 → 候选解释或情景 → 当前判断 → 最强反证 → 更新条件。**

其中“基准”随任务变化：个股近期表现看指数和行业；财报看冻结时点的一致预期；事件看参考类与同期盘口；主题看没有该主题时的需求和利润路径；人物看其权限、承诺和约束。

解释性研究可以在证据允许的地方给出“当前最支持哪个解释”。不需要为每句话附加免责声明。限制应集中写在会改变判断的关键缺口上；证据不足以区分解释时，明确下一项最有价值的调查。

### 2.3 对“Agent 越多越好”的修正

TradingAgents 展示了专业分工、多空辩论和结构化交接；FinRobot 展示了计算数据到分析文字、报告的组织方式。[S4–S5] 值得借用的是职责边界、数据交接、日志与先算后写。

这些研究不能证明增加角色可以普遍改善投研。共同材料、共同模型会共享错误，多空辩论也可能围绕错误前提展开。初版应由主研究者协调必要取证、确定性计算与一次独立审查；只有对照评测显示某个新增角色改善质量或成本，才保留它。

## 3. 类型一：事件定价／Polymarket

### 用户真正需要什么

弄清楚“这个合约究竟问什么、什么信息决定结果、当前概率为何如此、什么新信息值得更新”。市场价格是一个基准，独立研究应能解释与它相同或不同的原因。

### 最合理的分析链

1. **事件契约**：读取完整问题、规则、结算来源、时间与时区、澄清、争议和延期状态。区分现实事件发生与该合约结算为 Yes。同一 event 下的市场不自动互斥。
2. **参考类与基准率**：寻找适配的历史集合或已有模型。必须交代样本、条件和时间；找不到时保留缺口，不由模型随口生成“历史上 70%”。
3. **不看盘口的初判**：使用当时证据，列出少量关键驱动与条件关系。政策看程序和执行，选举看民调误差及地区相关性，财报看指标口径与预期。需要时使用条件情景树。
4. **概率一致性**：互斥且穷尽的结果合计为 1；阈值概率满足单调性；相关驱动不能直接当独立事件相乘。不展示没有统计来源的置信区间。
5. **市场比较**：保存同刻显示价格、bid/ask、深度与最近成交。另存看盘口后的判断与修订理由。显示价通常取中点，价差超过 10¢ 时可能使用最近成交；显示数值不保证能成交。[S12]
6. **触发更新与结算**：官方发布、关键数据、程序节点、规则澄清后更新；记录旧概率、新概率与新增证据。按合约真实结算复盘，取消／争议／延期也留在样本内。

盲于盘口的初判主要用于诊断锚定与增量信息，不保证优于使用市场信息。对同一个已公开讨论过的问题，也不能声称模型在训练记忆层面从未接触其价格。

### 成品

一张事件卡：合约定义、关键驱动、研究概率、同期市场、差异解释、下一节点与更新条件。按需附概率轨迹、结果分布和规则明细。用户没有问概率时，不强迫生成预测。

### 当前插件需改变的地方

本地 `forecast.py:54–58` 的 market 模式直接返回 market_prob；这完成了市场基准登记，没有形成独立估计。independent 模式将至少三次预测求均值；同一模型多次判断不等于统计独立。

建议把“市场基准”“研究初判”“参考市场后的最终判断”设为不同语义字段。新的方法版本需与旧档案隔离，旧记录不静默重算。保留多次生成可以检查稳定性，但不把次数当作置信度。

### 评测

前瞻影子预测，比对参考类、同期市场、单研究者检索和增加审查后的结果。二元用 Brier，多结果用预先固定定义的多类 Brier／log loss；log 的下限事先确定。报告校准、分辨力、题型、期限、样本数及成本。

同一事件的反复更新、相关子市场按事件簇处理，不充当大量独立样本。几十题足以发现流程缺陷，不足以证明稳定胜过市场。收益另需可成交价格、深度、费用与延迟，不能由预测分数直接推出。

Halawi 等的工作支持检索、预测、聚合这一组织方式，但整体结果并不等于普遍胜过人类。[S8] ForecastBench 支持持续前瞻评估。[S9] Metaculus 的开源工具可借问题类型、概率解析和日志；接入时必须将研究与对外提交分开。[S10]

## 4. 类型二：单一资产

### 用户真正需要什么

解释价格和基本面的变化，找到预期分歧，以及决定未来价值的变量。先识别用户问的是近期异动、财报、长期价值还是特定催化剂，再选择分析链。

### 最合理的分析链

**核实变化与比较基准 → 拆经营／供需驱动 → 对照市场预期 → 建情景与定价联系 → 检查反方与更新指标。**

以股票为例：

- “最近为什么跌”先算实际区间、相对行业与指数的表现，建立同窗事件线，再比较公司、行业、宏观等候选解释。时间重合与媒体叙述只是归因线索。只有研究设计支持时才讨论因果识别。
- 财报研究使用“实际 vs 原指引 vs 同期一致预期 vs 上年／上季”，核对财季、币种和 GAAP 口径。随后解释量价、产品组合、成本、营运资本与现金转化。
- 估值研究把收入、利润、资本投入、现金流与价格连接起来；情景有证据和敏感性。反向估值可检查当前价格要求什么增长和利润率，但不能在缺少必要输入时硬算一个目标价。

CFA 的估值流程强调理解业务、预测、方法选择和估值判断之间的连接。[S14] 这提供专业方法依据，不是对 Agent 效果的验证。

### 资产子类型不能共用一套财报模型

| 子类型 | 主要机制与数据 | 常见误用 |
|---|---|---|
| 股票 | 业务、资本投入、现金流、股权与企业价值、预期 | 收入增长直接推出股价上涨 |
| 指数／ETF | 成分权重、集中度、行业暴露、调仓、费用、跟踪 | 用一个代表公司的经营情况代替整个组合 |
| 商品／期货 | 供需、库存、成本、季节性、期限结构、持有与展期 | 将远期曲线直接当作未来现货预测 |
| 加密资产 | 发行销毁、解锁、需求与费用、参与者收益、安全机制、流动性 | 将协议活跃、手续费与代币持有人现金流混为一谈 |
| 债券 | 现金流、久期、利率与信用、违约和回收 | 将票息视为最终收益率 |

本轮对股票方法阅读最深；加密读取了 Ethereum 官方机制资料，发行／销毁与现有 ETH 转移需要分开。[S18] 商品、债券等表格是待验证的方法边界，没有完成它们的独立 playbook 或数据接入。不能把上述分类写成当前产品已经支持所有资产。

### 成品与评测

成品采用适配任务的“变化图＋关键指标对照＋经营到预期／定价的分析＋下一验证”。可以只输出财报解读，不附目标价或概率。

评测分别看行情计算、财务抽取、口径、预期时点、模型重算、解释完整性与引用支持。财务预测再按到期结果计误差；股价或收益另评。测试必须包含成长但现金弱、业绩好但低于预期、估值压缩、非美股口径等反例。

## 5. 类型三：行业主题

### 用户真正需要什么

判断一个叙事成立到哪一步，需求如何变成收入和利润，价值由谁取得。最重要的能力是发现传导断点，而不是生成更多“相关概念股”。

### 最合理的分析链

1. **可证伪命题**：定义地区、期间、需求对象和比较基准；把叙事拆成需求、交付、价格、利润四层。
2. **机制与价值链**：最终需求 → 采购／预算 → 产能／许可 → 交付 → 收入确认 → 利润／现金。标出时滞、瓶颈、替代路径及每条连接的证据状态。
3. **敞口**：识别具体产品、分部、客户与合同。分为已披露、可估区间、定性关联；未知不能填零，也不能填成主观份额。
4. **经济量级**：增量数量×单位价格×可取得份额，再考虑成本、折旧、扩产和营运资金。关键输入不足时输出敏感性或定性判断，停止给点估计。
5. **供需与财务交叉验证**：需求看预算、采购和使用，供给看产能和交付，财务看确认与回款。冲突先核对口径和阶段，不能简单取平均。
6. **反证与到期检查**：需求没有兑现、需求兑现但供给竞争稀释利润、企业盈利改善但价格已反映，分别处理。

IEA 的 AI 能源研究可以借鉴设备存量、利用率、效率和基础设施约束的分解方法。[S15] 该报告是方法示例，不代表本报告提供了截至今天的新需求预测，也不保证观察性分析具有因果识别能力。

### 成品与评测

成品包括机制图、环节／企业敞口矩阵、经济量级分析与领先指标面板。首页应直接写“目前成立到哪一层、最大断点是什么”。

验收引用与计算后，由盲评者检查必要机制、替代解释、利润归属和反证覆盖。到期再检验数量区间、交付与利润方向。与同材料、同预算的资讯摘要和通用个股模板比较。主题被有依据地否决也是有价值的结果。

FinResearchBench 的逻辑结构评价可作辅助，但树更深、节点更多不等于机制更真实。[S6] 不应用“多写几个推理节点”来优化报告分数。

## 6. 类型四：人物／机构

### 用户真正需要什么

了解这个主体有什么权限、在什么约束下作决定、说法与行动是否一致，以及它们如何影响资产或事件。不能把媒体口碑或公开形象直接变成预测能力。

### 最合理的分析链

**市场相关问题 → 权限与约束 → 原始条件性表态 → 当时信息 → 可观察行动 → 表态／行动／结果比较 → 替代解释 → 更新条件。**

| 子类型 | 必须分析 | 不能直接推出 |
|---|---|---|
| 央行 | 目标、委员会规则、数据版本、条件性沟通与投票 | 某一人的语气必然决定下一次会议 |
| 公司管理层 | 指引、资本配置、治理、激励、授权与实际执行 | 宣布回购额度等于已经完成回购 |
| 基金／投资机构 | 策略约束、公开论点、可披露持仓及披露滞后 | 13F 是当前完整组合或确切交易记录 |
| 监管机构 | 法定权限、程序、司法约束、提案到生效和执法 | 提案已经生效，或者表态等于可执行规则 |

SEC 的 13F FAQ 明确季末报告及披露范围等限制：空头等信息并不完整，不能据此还原当前净敞口。[S16] 央行沟通也可能同时揭示政策和经济信息，简单将讲话与股价同向／反向视为因果会混淆机制。[S17]

### 成品与评测

成品为权限约束卡、表态—行动时间线、承诺兑现表或条件反应图。actor 可以独立研究长期反应规律，也常作为事件、资产或主题的一个分析视角；不强迫输出人物传记。

评测看原文条件是否保留、个人与机构归因是否正确、授权／宣布／完成是否区分、信息时间是否对齐。预测能力需要全量事前登记，控制题目难度、提前量、相关性与样本数。现有少量样本命中率不能直接充当作者可信度总评分。

## 7. 共享架构与差异化分析

四类应共享证据账本、时间版本、计算、引用、归档和渲染；分别维护分析步骤和必须回答项。

路由需要两个维度：

- **对象**：event_pricing / asset / theme / actor；可以组合。
- **任务**：现状速览、变化解释、预期／定价比较、前瞻预测、持续跟踪。

例如“某央行决定对金价有何影响”可以是资产主问题，包含事件预测和机构反应分析；不必机械选择一个模板后放弃其他需要的分析。

研究控制应从“固定角度不能增删”改为“必须回答项＋可选调查模块”。来源不限于最近 30 天：近期变化需要新证据，参考类、制度和业务结构可能需要多年材料。Last 30 Days 继续承担社区搜索、去重、聚类和诊断，不能成为所有研究资料的时间边界。

综合阶段按重要性、变化量和对判断的影响筛选材料。审查阶段检查具体漏洞：事件看规则和概率一致性，资产看口径与估值连接，主题看必要条件和利润归属，人物看条件与权限。编辑阶段才确定首屏、正文、图表与证据展开层。

## 8. 输出质量如何验收

### 8.1 基础门槛

- 关键主张有真实支持，来源层级正确；引用存在不等于支持成立。
- 数字有期间、单位和计算输入；计算与图表可重算。
- 价格与预期匹配研究时点；修订资料保留版本。
- 事实、推断与预测在结构数据中区分；网页里用自然语言和适量标注表达。
- 核心任务缺少决定性资料时，结果明确为部分完成，不靠排版补齐。
- 不以模板默认值、零值或固定增长率冒充获取成功或研究判断。

### 8.2 研究与阅读价值

由对研究结论不知情的评审，在同一问题、资料、时点和预算下比较：

- 有没有直接回答原问题？
- 有没有指出最重要的变化及其意义？
- 机制和竞争解释是否站得住？
- 有没有新的、有依据的区分，而不只是转述更多资料？
- 有没有说明什么会改变当前判断？
- 用户能否迅速复述主判断、理由和下一观察？

LLM 可以检查格式或辅助评分，不能单独决定所有结论。精美页面、字数和引用数量不设为研究质量加分项。

### 8.3 三层验证集

1. **12 个开发案例**：四类各三题，用于发现任务契约与资料缺口。它们是开发夹具，不能同时当最终测试成绩。
2. **未参与设计的保留案例**：按类型和难度覆盖成功、冲突、部分完成和不成立，验证是否能迁移。
3. **前瞻记录**：事件概率、财务预测与主题里程碑按预先规则追踪，检验到期表现。

报告成本、延迟、来源成功率和完成率。加入审查、聚合或更多代理的收益，需在相同预算下做对照；必要时同时给质量—成本取舍。

## 9. 需要的调研已到什么程度

本轮已经足以修正产品方法和下一阶段顺序，不建议继续无目标堆论文。更高价值的工作是用四类代表问题检查这些方法能否生成有用成品。

仍有明确未完成项：没有运行外部 Agent 项目，没有复现论文实验，没有实跑本轮四类案例，没有验证全部资产子类型，也没有测量改造后的效果。本文的“建议”是根据专业方法、论文、源码及当前插件缺口推导出的设计选择，不是已证实的最优解。

文献阅读深度不一：主要读取摘要、方法／实验相关正文及选定源码；部分长论文未全文通读。下表标明证据用途，避免把作者自述误当本产品已验证能力。
