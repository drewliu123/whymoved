# 盈利质量示例：微软 FY2024–FY2025

这个示例只用[微软现金流案例](../msft-cashflow/research/evidence/official-tables.json)里已冻结的官方表格数字，演示如何把两期报表转成趋势、现金转化与红旗筛查。

```bash
python3 scripts/financial_quality.py examples/msft-quality/statements.json
```

## 输入来源

| 指标 | FY2025 | FY2024 | 来自 |
| --- | --- | --- | --- |
| 收入 | 281,724 | 245,122 | 年度业绩表 |
| 毛利 | 193,893 | 171,008 | 年度业绩表 |
| 营业利润 | 128,528 | 109,433 | 年度业绩表 |
| 净利润 | 101,832 | 88,136 | 年度业绩表 |
| 经营现金流 | 136,162 | 118,548 | 现金流量表 |
| 资本开支 | 64,551 | 44,477 | 现金流量表（购置固定资产） |
| 折旧摊销 | 34,153 | 22,287 | 现金流量表 |
| 股权激励 | 11,974 | 10,734 | 现金流量表 |

金额单位为百万美元，期间为微软财年（7 月–次年 6 月）。

## 结果摘要

| 指标 | FY2025 | 含义 |
| --- | --- | --- |
| 毛利率 | 68.82% | 同比 −0.94pp |
| 营业利润率 | 45.62% | 同比 +0.98pp |
| 净利率 | 36.15% | 同比 +0.19pp |
| 现金转化（CFO/净利） | 1.337 | 同比 −0.008 |
| 资本开支/收入 | 22.91% | 重资产投入期 |
| 资本开支/折旧摊销 | 1.89 | 扩张性投入，不是维护性不足 |
| 股权激励/收入 | 4.25% | 稀释压力可控 |
| 增量利润率 | 52.17% | 新增收入的利润贡献高于存量 |

红旗：**无**。收入增长 14.9%、利润率稳定、现金转化高于 1、资本开支高于折旧、股权激励占比低于 10%——这正是筛查器不该制造噪音的情形。

## 用固定模型复现官方报表

同一份示例数字还被用来验证两个固定模型是否真的能复现已披露的损益：

- `operating_bridge`：基期 FY2024 收入 245,122、营业利润率 44.64%，收入增长 14.93%、情景利润率 45.62% → 复现 FY2025 收入 **281,724**、营业利润 **128,528**、利润变化 **19,095**，且收入效应 + 利润率效应恰好等于变化量。
- `driver_build`：[分部数据](segments.json)（三大分部 FY2024/FY2025 收入与营业利润）→ 量增长取实际收入增速、价增长为 0、分部利润率取 FY2025 实际值，复现总收入 **281,724**、营业利润 **128,528**，增量利润率约 **46.3%**。

这两条回归在 `tests/test_analysis_models.py` 里执行；它们证明模型的算术与口径定义能对上真实报表，而不只是自我一致。

## 这个示例故意缺什么

- 没有资产负债表科目（应收、存货、应付、总资产、权益、债务、现金），所以 DSO/DIO/DPO、现金周期、应计比率与 ROIC 都是 `null`，而不是猜一个数字。
- 没有股本与税率，所以没有 ROIC 与稀释率。
- 各字段没有 `claim_ids`，因此输出的 `unattributed` 会列出它们——说明数字来源尚未接入主张账本。真实研究里应逐项挂到 claims。

缺口被显式记录而不是填补，是这套工具的设计要求：`null` 代表「没有输入」，不是「指标为零」。

## 边界

筛查器输出的是**核查提示**，不是舞弊判断，也不是投资结论。阈值（如应计比率 10%、现金转化 80%、应收天数 +15%）是经验默认值，行业差异很大，研究者可在调用时覆盖。真正要判断的是：这些变化在当期披露里有没有合理机制。
