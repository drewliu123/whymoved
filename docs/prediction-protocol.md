# 预测协议：从「解释」转向「可证伪的下注」

这份文档定义本项目的预测实验。目标不是保证阿尔法，而是让判断可以被时间证伪。

## 一条预测必须包含

| 字段 | 含义 | 反例 |
| --- | --- | --- |
| 共识/基准预期 | 市场或趋势外推的默认判断 | 「大家觉得会涨」 |
| 本报告预测 | 可量化的阈值与方向 | 「前景谨慎乐观」 |
| 期限 | 具体日期，到期才能打分 | 「未来」 |
| 比较基准 | 相对什么 | 「表现不错」 |
| 失效条件 | 什么出现就认错 | 「逻辑破坏」 |

缺少任何一项，不算预测，只是观点。

## 共识数据的诚实边界

本机无法取得分析师一致预期（consensus）。因此「共识」一栏是**公开叙事或趋势外推**，不是调查数据。每一条都在预测日志里注明 `consensus` 原文；读者应把它当作「本报告假设的共识」，而不是市场真实预期。这是当前方法的最大限制。

## 打分规则

- 到期后，用官方披露值（SEC XBRL 或公司财报）作为 observed。
- `below`：observed < threshold 为 hit；`above`：observed > threshold 为 hit。
- 到期前不允许打分；每条只能打一次。
- 记录 observed 与 scored_at；不删除、不改写历史。

```bash
python3 scripts/prediction_log.py --file predictions/2026-11.json list
python3 scripts/prediction_log.py --file predictions/2026-11.json score --id P1 --observed 32.5 --date 2027-08-01
```

## 如何解读结果

- 5 条样本没有统计意义，只能说明判断是否被证伪，不能证明能力。
- 命中要区分「预测正确」与「基准太容易」；未命中要记录原因，而不是修改原预测。
- 真正的阿尔法还需要仓位、成本、风险预算与组合约束；本实验只验证**判断**这一层。

## 维护

- 每条预测到期后 30 天内打分；过期未打分标注 `overdue`。
- 新报告可以带预测，但必须进入本日志，否则不算。
- 不为了命中率修改阈值或期限。
