# 持续迭代计划（Iteration Program）

本目录记录「投研助手 / Touyan」插件从 2026-11-14 起的长周期迭代：目标、待办清单、每轮记录与验收方式。
它不是给终端研究读者看的报告，而是维护者与 Agent 的接力棒：**任何人（或下一轮自动续作）读这三个文件即可继续工作，不必重新审计全仓。**

## 三个文件

| 文件 | 作用 | 何时更新 |
| --- | --- | --- |
| [backlog.md](backlog.md) | 按价值/成本排序的待办卡片（含验收标准、风险、涉及文件） | 每轮开始认领、每轮结束更新状态 |
| [log.md](log.md) | 每轮做了什么、为什么、验证证据、遗留问题 | 每轮结束追加 |
| [rubric.md](rubric.md) | 「更有投研意义」的可检验判据：一轮改动必须让哪条判据前进 | 需要修改评价标准时 |

## 迭代目标

插件已经具备：计划契约、来源/主张账本、分析契约（问题→方法、竞争解释、区分检验、市场隐含预期）、四个固定财务模型、独立红队审查、同源 Markdown/HTML、不可覆盖归档。

**缺口不在流程严谨度，而在投研方法厚度**：能解释变化，但还不能像分析师那样做相对估值、搭驱动式经营模型、检查财务质量、维护催化日历、跨轮次积累论点。

因此每一轮都遵循同一模式：

1. **选一张 backlog 卡片**（优先高价值/低成本、能独立验证的）。
2. **先写验收标准**：确定性脚本的输入/输出、契约字段、渲染结果、测试用例。
3. **实现**：新能力优先做成独立确定性脚本或 analysis_models 新模型；尽量不破坏旧归档兼容。
4. **测试**：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests` 全绿；新能力必须有边界与失败用例。
5. **文档**：references 里写清「什么时候用、怎么用、边界在哪」，CHANGELOG 记一条。
6. **提交**：本地 commit（不 push，推送由用户手动执行）。
7. **记录**：log.md 追加本轮条目，backlog 更新状态。

## 不可违反的既有原则（每轮自检）

- 确定性工具只做结构、引用、时间与固定算术检查，**不冒充语义或因果证明**。
- 不给个人买卖指令；输出研究判断、检验条件与失败代价。
- 不制造精确概率、不为凑发现添加内容；缺数据写 missing 并说明对判断的影响。
- 旧归档、旧 schema 保持可读，不追溯改写结论。
- 新增字段必须有校验、有测试、有文档，不能「写了就算」。
- 中文文档与中文输出；代码注释与既有风格保持一致。

## 一轮的完成定义（DoD）

一轮只有同时满足以下条件才算完成：

- [ ] 新能力有可运行入口（脚本或模型 kind），并对真实输入跑通至少一次
- [ ] 有正例 + 反例/边界测试，全套测试通过
- [ ] 至少一处 references 文档说明用途与边界
- [ ] CHANGELOG 有记录
- [ ] backlog 状态与 log 条目更新
- [ ] 本地 commit（一个逻辑单元一个 commit）

## 如何续作

```bash
cd "/Users/frankzhang/Desktop/03_AI工具与插件/投研助手"
cat docs/iteration/backlog.md | head -60   # 看当前最高优先级卡片
tail -40 docs/iteration/log.md             # 看上一轮做到哪、有什么遗留
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
```

若上一轮留下了「半成品」，优先补完再开新卡片；不要同时开两张会改同一文件的卡片。
