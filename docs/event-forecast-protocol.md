# 事件方向预测协议

用户要求：在高波动事件前，给一个方向判断，尤其是非共识的「隐藏方向」。这份协议定义怎么下判断、怎么认错、怎么打分。

## 一条事件预测必须包含

| 字段 | 含义 |
| --- | --- |
| 事件与时间 | 具体财报/会议/数据，含盘前盘后 |
| 共识 | EPS/营收/宏观预期；拿不到就写「不可得」 |
| 方向 | up / down（T+3 收盘相对事件前收盘） |
| 把握度 | low / medium-low / medium / high（主观，不是概率） |
| 隐藏方向 | 与共识不同的点：为什么市场可能定价错了 |
| 失效条件 | 价格、基本面或指引出现什么就认错 |
| 打分日 | 具体日期与基准价 |

## 方向判断的来源

只允许三类依据：

1. **估值与位置**：P/E、P/B 相对自身历史；价格距 52 周高低点；事件前是否已经出清。
2. **基本面质量**：收入/利润/现金流/DSO/库存；是否出现「增长放缓 + 现金恶化」双杀。
3. **共识与分歧**：市场在担心什么；我们的不同点是什么；如果没有不同点，就不下注。

不允许：凭感觉、凭叙事、凭「这次不一样」。

## 打分规则

- 方向 up：T+3 收盘 > 事件前收盘 → hit；否则 miss。
- 方向 down：T+3 收盘 < 事件前收盘 → hit；否则 miss。
- 到期前拒绝打分；每条只能打一次；记录 return_pct 与日期。
- 一次结果不能证明能力；至少 20 次同类型事件再谈胜率。

## 修正规则

预测在事件发生前可以修正，但必须保留修正记录与理由；事件发生后不允许改方向。NVDA 的 E1 就从「偏多」改为「偏空」，原因写进了事件笔记。

## 与「催化剂日历」的关系

日历回答「什么时候可能波动」；本协议回答「往哪个方向、凭什么、什么时候认错」。两者一起用，不把日历当方向预测。

## 边界

- 没有期权隐含波动、没有真实营收 consensus、没有机构 positioning 数据。
- 事件方向判断不是投资建议，也不是长期评级。
- 财报日期/时间变化时，预测失效并重写。
