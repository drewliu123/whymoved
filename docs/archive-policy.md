# 档案保留与版本策略

本仓库保留完整研究历史。目录索引用于说明材料身份和找到入口，不通过删除、移动、改名或覆盖旧文件来整理历史。既有相对路径保持稳定，避免历史报告、来源和审查记录之间的链接失效。

## 材料边界

| 类别 | 代表位置 | 阅读与保留原则 |
|---|---|---|
| 当前产品实现 | [skills/](../skills/)、[agents/](../agents/)、[scripts/](../scripts/)、[tests/](../tests/) | 以当前提交和安装说明为准；历史目录中的探索脚本不自动成为产品入口。 |
| 真实取证与运行快照 | [SEC 接入记录](../evidence/sec-integration-20261102/README.md)、[研究 runs](../journal/runs/) | 保留原始返回、来源与时间、精确对象/期间、失败及完整性状态；真实获取不自动证明经济解释正确。 |
| 模拟响应、离线回归与 fixture | [重建回归](../evidence/rebuild-20261031/regression/SUMMARY.md)、[自动测试](../tests/) | 标清固定输入、模拟响应及断言边界；通过只证明给定条件下的行为，不冒充新的联网取证。 |
| 历史研究、实验与原始资料 | [研究索引](../research/README.md)、[证据索引](../evidence/README.md)、[研究档案](../journal/README.md) | 保留当时原文、协议、结果、限制和版本。人工构造实验、历史真实事件与当前研究分别标注。 |
| 临时工作痕迹 | [journal/work/](../journal/work/)、journal 下 tmp 文件、各批次 work 目录 | 用于追溯输入、来源选择、生成和审查；不是额外产品，不因命名为 tmp 就自动清除。 |
| 本机配置与缓存 | data 下 sec-cache 与 sec-runtime.json | 本地保留、从 Git 跟踪中排除；不能代替应归档的原始研究证据。其他历史数据账本不随之清除，见[数据索引](../data/README.md)。 |
| 历史交付包 | [delivery/](../delivery/README.md)、[四类验证 ZIP](../journal/four-type-validation-20261031-delivery.zip) | 保留旧包、旧清单和原路径；包的旧版本不能被当作当前安装版本。 |

## 修订与追溯

新研究使用新 run；更新研究保留父 run，另存新增来源、修订判断、比较口径与审查记录。纠错应新增更正记录并关联旧结论，说明改了什么、依据是什么、何时知道；不改写原报告以消除先前错误，也不使用后来获知的事实补写事前判断。

已冻结的协议、输入、原始输出、清单和哈希按原件保留。旧 schema 不因当前契约变化而追溯改造或重判。需要重新渲染、重新验证或重新抓取时另存输出，注明所用提交、工具/运行时、输入版本、执行时间、结果和局限；离线复核旧快照与重新联网获取必须分开记录。

索引可以新增或更新说明，原有文件内的日期、绝对路径和历史状态仍作为历史记录保留。入口名称不能把旧报告升级为“当前已联网验证”；真实取证、模拟 fixture、人工实验与待核实判断都须按原记录区分。索引中的代表入口不替代对完整材料的逐项审查。

## 未来 ZIP 与 Release

重新生成交付 ZIP，建议从明确 tag/提交生成新版本文件，并发布到 GitHub Release 附件，附提交号、生成方式、文件清单、校验和、依赖/子模块获取方式和验证范围。打包前区分必要研究证据与本机缓存、配置、凭据，不把本机状态当成可移植依赖。

这是一项后续发布建议，不要求当前删除、移动、重命名或替换已有包。已有 ZIP、交付清单、研究底稿与完整证据历史继续保留；新包与新清单另存，相关索引可追加新入口。
